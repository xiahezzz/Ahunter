# LAgent 执行内部契约

状态：2026-09-09，LE-007 实现中。`ExecutionEngine` 目前是宿主调用的市场执行层，
不是 Agent 的 submit_plan API，也不证明整个 Episode 可正式评分。

## 交易规则与接受顺序

`accept_batch` 接收宿主已确定的交易所接受时点、Reservation 与每证券唯一的
AcceptanceEvidence。交易日、有效规则、接受时间窗、tick、价格界限、适用价格笼子、
买入最小/增量、最大申报数量、成交精度均验证。卖出最小量、增量及全部可用零碎余额
例外来自显式历史证据，不能把买入数量规则或当前规则套给卖出。价格笼子需要来源
给出的实际边界，不凭缺失参考价猜算。测试全为 synthetic，未验收真实法规来源。

整批资源由账户暂存器验证，末尾任何订单失败均不发布先前订单；已有同证券反向有效
委托也拒绝。接受时间与递增优先序永久保存，JSON 对象排序不改变成交优先级。
本层接受的是已证明的市场接受事实；平台阶段计划通过下述 StagePlans 调用，不能
让候选直接调用 accept_batch 绕过阶段约束。

## 普通完整分钟

MinuteEvidence 明确原始完整分钟、有效规则、成交股数、价格界限、状态及公司行为
覆盖、来源引用/哈希与可用时点。只接受连续竞价区间内完整、对齐的 60 秒；不把竞价
算进普通分钟。接受时间必须严格早于分钟开始，恰在边界或分钟内接受都不给该分钟回填。

买价 = high + sealed minute_slippage_ticks × tick；卖价 = low − 对应滑点。限价、
市场边界或容量条件不满足时记录 model_no_fill 及原因，不把触价当作成交保证。
整体停牌且无成交的证据可解释 no_fill；部分停牌、复牌、集合竞价、撤单/成交竞争、
涨停买入或跌停卖出等要求队列时，缺实现/证据报 execution_evidence_missing，不转零成交。
当前对于买侧分钟达到涨停价、卖侧达到跌停价保守路由到队列，不能以分钟高低点声称
前方队列被消耗。

每 Test/证券/分钟只有一份 capacity：历史成交股数 × sealed participation_rate，
向下取整到规则 fill_increment。所有有效订单按接受时间/稳定序号共享容量，允许部分
成交，不为每单重置比例。已处理分钟的换身份重放拒绝，同身份同输入重试返回原事件。
同一共享容量记录绑定成交量、规则及来源；后续队列引擎必须复用这条容量约束，不能
另开一份容量。队列重放现在使用相同容量存取函数；分钟一旦由一种路由处理，另一种路由不能再次消费。

## 原子记账与回放

`SimulatedAccount.stage()` 返回内存暂存器，复用现有费用、税务、FIFO、回执与资源
校验；暂存不发布中间账户状态。整分钟完成后，一个带租约和版本检查的账户事件同时
写入 account 与 execution 投影，保存每笔效果、源证据及无成交原因。部分失败不会
留下已用容量或已扣现金。既有 NAV 和 observed 账户仍按同一事件与累计回执可用时间
读取，避免容量/账户分离提交造成双花或重复成交。

## 完整队列与固定竞价

`QueueReplay.advance` 接收完整 QueueEvidence：起始订单簿、连续交易所事件序号、
每条事件的时间、可重建对手方、同一历史路径的分钟成交量、插入位置来源及固定场景路由。
每个模拟单的 after_sequence 来自接受时点的来源证明，并在该历史流中固定，不能重放
时提前。相同历史序号之后的模拟单仍按平台保存的稳定接受顺序排列；价格优先于时间。

历史 add/cancel/match 只改变历史簿；模拟单只改变自身账户。匹配时必须证明真实参与方
符合历史限价与价格/时间优先级，前方历史单未消耗完不会给模拟单量。已知取消只减少
被取消的真实批次；未知 ID、数量不足、重复身份、序号/时间缺口和遗漏对手方都失败。
在历史匹配实际让出机会时，模拟单才按同一匹配价分配，并共享全 Test 的分钟容量。

开/收盘竞价要求覆盖整个对应区间，复牌竞价要求显式完整来源区间；每个竞价匹配必须
位于同一证明时点、使用同一个原始成交价，逐笔量与竞价/分钟量均一致。零成交且没有
可执行对手方可以 no_fill；零成交却遗留相交可执行订单则证据矛盾。完整价量或已知前方
队列未消耗得到 model_no_fill，不能与 execution_evidence_missing 混淆。

连续竞价队列目前用于原定涨停买入/跌停卖出场景，并要求来源捕获实际包含该价格界限，
或无成交时有对应界限上的排队证明，不能随意选择更有利的成交模型。非零额外队列滑点
暂不支持，明确失败，不修改固定历史匹配价。

宿主可指定 through_at/through_sequence 提交一个已证明的前缀。完整来源捕获先验证，
不能通过提前停止隐藏后方损坏数据；只处理前缀内事件，后续从持久历史簿/序号恢复。
下一捕获必须与前一结尾簿和序号连续。完整原始证据保存为宿主不可变 artifact，前缀
账户事件只保留证据哈希和截至截点的效果，不内嵌未来逐笔内容。后续 Episode 编排必须
在每个观察、计划和撤单边界切分回放；主/子 Agent 不得直接读取宿主完整证据 artifact。

## 阶段计划与撤换

`StagePlans.submit` 接收宿主构造的 main PhaseSession、StagePlan 及历史市场证据。
只有指定的根主会话可以提交，子会话即使复用主 actor 名称也没有计划权限。当前 Phase
必须有效且允许交易，租约、截止时间与作用域在写事务内再次检查。每阶段只记录一次
成功接收；校验拒绝不占用名额。同 plan_id 同内容的通信重试返回原事件，即使传输
action_id 改变或阶段已经关闭；改变内容报告 conflict。该接口目前仍是宿主内部接口，
其原始账本返回值不得直接透传候选，未来运行器需提供范围受限的响应。NewOrder 中
的规则/费用及市场证据是宿主补全字段，后续候选工具只接收交易意图，不能让候选填费率。

计划按列表验证 new/cancel/replace 指令，独立新单只冻结当时实际可用资金/证券，
不使用同计划预计卖款或撤单释放。重复引用旧单、复用新身份、跨方向自成交冲突、
低于旧单已成交量的目标均整份拒绝。预定替换 ID 在成功接收时保留，不能在等待期间
被别的批次占用；它不提前冻结替换资金。新单处于 pending_acceptance，尚不参与撮合。

平台接收、市场接受、撤单生效与回执分别使用封存时间/延迟。等待市场的批次不得跳过
较早工作流事件。市场动作如位于可能撮合的区间，必须先将队列推进到来源证明的同一
时间/序号游标；缺失不凭时间排序默认值完成动作。新单在真实模拟接受时再校验价格
笼子，市场拒绝后的资源直到拒绝回执才释放，零成交不收费。

撤单请求不释放资源，旧单在固定生效时间前继续接受有证明顺序的成交。到生效点先停
旧单，回执前保持资源冻结；确认回执后释放，撤换数量 = max(0, 合计目标 − 旧单累计
成交)，再验证数量规则、资金和同日接受窗口。数量/资源不足记录 replacement_rejected，
不缩量或改价，旧成交和取消不回滚；目标已满足不下新单。新单重新分配接受优先级及
最低佣金预留。禁止取消或取消太迟分别记录失败，旧单按实际状态继续，不无限重试。

DAY 到期需完整收盘竞价游标及有效收盘规则，在收盘＋封存回执延迟时释放残留资源。
未处理的较早工作流不能被到期跳过；等待流程终止，不跨日重新挂单。空仓/无活跃订单
也必须给出明确有效收盘规则。账户新增等待接受、生效后待回执、拒绝后待回执等状态，
它们继续占用冻结资源；FIFO 重分配及企业行动/特殊结算检查均包含这些状态。
