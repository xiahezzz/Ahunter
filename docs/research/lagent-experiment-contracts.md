# LAgent 实验配置与模块 Interface

状态：契约摘要；剩余核心规则已定稿，待按 tickets 实施。更新于 2026-09-09。实施以[设计定稿](lagent-experiment-final-design.md)为准，开发任务见[tickets 索引](../tickets/lagent-experiments/README.md)。

本文件将[已讨论的设计与决策](lagent-inner-loop-evaluation-design.md)收敛为模块契约摘要。已确认的交易、信息、预算和留存规则保持不变；下列操作不是现有 API 或 CLI 命令；定稿 D09/D12 固定其生命周期与交付语义。

## 配置归属与冻结

experiment 接收原始配置，调用各模块验证并解析规则引用，保存完整生效配置和哈希；各模块拥有字段的含义与校验，不由 experiment 重写交易、成本或评分逻辑。配置不完整时可以保存草案，但不能进入正式评测队列。

| 配置区域 | 拥有模块 | 内容与当前决定 |
| --- | --- | --- |
| task.period | experiment | 研究启动时间；交易期间选择起止日期或开始日加交易日数，保存日历解析后的日期列表 |
| candidate | experiment / 内层 LAgent | 候选实现、提示词及依赖产物引用，模型与推理档位，允许调优配置及父版本；固定规则不随候选变化 |
| env.clock | env | 时区、竞价成交前/竞价后/盘后阶段、各自信息截点、平台接收时间、申报时序与延迟；模型现实耗时不推进模拟时间 |
| env.data | env | 数据产品及版本、各产品可用时间映射、搜索服务/日期条件/信任政策、数据窗口与质量门槛 |
| env.market_rules | env | 沪深 A 股、排除北交所；版本化日历、证券状态、价格/数量规则及费用 |
| env.account | env | 初始资金/持仓、账户制度、可用信用、资金与证券可用规则、冻结/释放、估值及适用债务 |
| env.execution | env | 固定历史行情路径、成交与排队模型、参与量限制、滑点、所需证据、撤单及受限撤换时序 |
| budget | budget | 每任务同等总成本、价格表、环境/评测预留、外层优化成本分账；无单独 token 上限 |
| runtime | runtime | 隔离执行、模型调用、并发/超时/重试、取消等待及恢复参数；主/子任务共用 Episode 预算 |
| evaluate | evaluate | 任务划分、重复运行与权重、期末收益计分、质量门槛、比较与晋级政策 |
| trace | trace | 查询/导出与可见性设置、产物保存引用；所有版本测试记录永久保留，不提供关闭必要审计的选项 |
| optimizer | 外层 optimizer | 下一阶段的提案模型、可修改范围、迭代与停止政策；首版使用手工/编码任务提交候选 |

每个数值字段声明单位、合法范围、默认值来源以及是否支持无限制。`null` 仅在字段明确定义时表示无限制，不能同时表示用户尚未填写；缺少必需值用明确的配置错误表达。修改平台条件产生新实验定义；修改允许变化的内层实现/配置产生新候选，旧记录不覆盖。

当前案例固定模型为 GPT-5.5 high，初始资金为 200000 元，2026-08-02 启动、交易期为 2026-08-03 至 08-07。金额、日期和持续交易日数都是案例配置；资金制度、精确阶段时间、成交模型及比较参数见定稿 D02～D10；同等成本金额按固定标定公式派生，真实标定尚未执行。

## 模块调用与所有权

这些是同一应用内的逻辑模块，复用已有 API、队列和任务执行所有权，不新增一套竞争调度器，也不要求拆成独立服务。

| Module | Interface 草案 | 对调用者承担的行为 |
| --- | --- | --- |
| ahunter CLI | 提交、查看、取消、导出实验；注册候选；请求比较 | 调用本地 API，返回身份及状态；不模拟交易、不计分，不把 HTTP 成功当作测试完成 |
| experiment | resolve、register_candidate、submit_tests、read、cancel | 固定配置、候选和任务身份，预检、持久排队、调度阶段、保存结果及进化树；仅此模块拥有运行调度权 |
| env | create_episode、observe、query、submit_plan、advance | 数据可见性、模拟账户和委托执行统一收口；内部 clock/data/market_rules/account/execution 不直接暴露给 agent |
| runtime | run_phase、stop_phase | 根据绑定的候选、阶段、信息视图和预算授权执行主/子任务，回收进程及迟到结果；不决定交易时钟和账户结果 |
| budget | reserve、settle、read | 调用前原子预留，调用后记录实际成本并释放多余预留；未知消耗保持待核实，不按零计费 |
| evaluate | assess、compare | 检查 Episode 有效性、读取 env 期末净值计分、汇总预定样本并比较当前基线；不启动第二套调度或改写成交 |
| trace | append、read、export | 保留不可覆盖的事件及产物关联，按操作者/内层/optimizer 提供不同视图，不记录模型私有推理 |

evaluate 拥有任务集及评分政策的含义和校验，experiment 根据已解析的任务清单安排执行。模型、env、evaluate 都不能自行回滚模拟市场、改测试期间或修改当前运行的候选版本。

任务角色包含开发/调优、用于选择的隐藏验证和最终留出；角色及反馈使用历史随任务记录留存，曾用于改进的期间不能通过改名恢复为未见任务。已确认原定 2026-08-03 至 08-07 用作首个调优基准，最终留出另选未参与调优的期间，预留选择验证和最终留出日期及 exposure 规则见定稿 D10。

## 内层能看到与调用的内容

平台为每次运行绑定 experiment、candidate、test、episode 和 phase 身份；这些身份及当前截点不是模型可任意改写的查询参数。主/子 agent 的数据调用都经过相同的 env Interface。

| 操作 | 输入 | 返回或副作用 |
| --- | --- | --- |
| observe | 当前阶段的绑定上下文 | 阶段截点、届时可见的账户/委托/回执及适用规则；不返回未来行情或其他候选结果 |
| query | 数据产品/查询内容与允许的筛选参数 | 带来源、时间语义、质量状态和产物引用的结果；搜索截止条件由平台注入 |
| delegate | 主 agent 指定研究任务及允许配置 | 同一阶段内的研究产物与调用记录；子任务不能提交交易计划或扩大数据权限 |
| submit_plan | 当前阶段计划及提交身份 | 整份接收或整份拒绝的回执，仅主 agent 可调用；接收不等于成交 |
| finish_phase | 当前阶段研究产物与完成声明 | 声明本阶段结束；平台回收执行权限并推进预定下一阶段，agent 不选择下一观察时间 |

这些交易动作仅存在于隔离的历史实验 env，不向当前业务 LAgent 的研究报告追加真实交易能力，不连接券商或写入实际交易账本。

## 计划与委托流程

一份阶段计划包含计划身份、阶段及快照引用、研究产物引用和有序指令列表。平台保存原始提交内容和解析结果；通信重试复用提交身份，修改内容必须形成新提交，不能覆盖原回执。

| 指令 | 必须预先确定的内容 | 接收与执行约束 |
| --- | --- | --- |
| 新 DAY 限价单 | 证券、方向、数量、限价、目标交易日 | 提交时已有可用购买力/可卖持仓，含费用校验；不能依赖同阶段未成交卖单回款 |
| 撤单 | 既有委托身份，撤销其未成交剩余部分 | 平台可盘前接收请求，按市场接受时段执行；撤单确认前不释放资源，先发生的成交有效 |
| 受限撤换 | 旧单身份、同证券同方向的新限价、原单与新单合计目标成交数量 | 先撤销确认，再扣除旧单累计成交量并校验新单；价格不变，目标完成不重挂，撤单失败或资源不足不擅改计划 |

整份计划校验包含跨指令资源冲突和同一旧单的冲突操作。独立新单接收时冻结资源；受限撤换接收的是依赖流程，不能提前把新单记成已获交易所接受，也不能重复冻结旧单尚占用的资源。流程就绪时再次检查资金、持仓、交易规则及有效期，检查失败保留结果。

竞价后的计划不替换或回滚竞价前的整份计划；只处理明确引用的旧单并增加通过校验的新指令。未被明确撤销的旧单继续按规则执行。竞价买入不自动获得当日可卖资格，资源是否可用由配置的历史市场与账户规则判断。

## 一天的阶段推进

1. **竞价成交前研究**：读取较早的固定快照，主 agent 可研究、委托和提交买卖计划。这里的“竞价前”指最终集合竞价成交之前，不要求所有研究都在 09:15 前；具体研究和申报时间由配置决定。
2. **env 推进开盘竞价**：停止本阶段模型工作，按申报时序和证据生成模拟成交、未成交及资源变化。
3. **竞价后研究**：在预定阶段读取已公开的最终竞价结果、届时可见的自身回执和账户；以实际可用净回款提交新单、撤单或受限撤换，全部模型决策在 09:30 前结束。
4. **env 推进交易时段**：执行既有 DAY 委托和预提交撤换；09:30 起不调用主/子模型，不根据盘中消息形成新决策。
5. **盘后研究**：23:00 后的配置时刻读取复盘快照，更新任务记忆；最后交易日的收盘净值评分不因盘后研究改变。

初始 08-02 的研究使用独立盘后阶段，预设 23:05:00+08:00。所有时刻和回执延迟均配置化；模型现实耗时单独记录，不推进上述模拟时钟。

## 生命周期与记录

一个 Test Record 对应一个候选在一个任务上的一次预定重复运行，包含独立 Episode；跨任务汇总另存 Comparison Record，避免把整组比较和单次试验混为同一记录。

Test 生命周期为 `created → preflight → queued → running → evaluating → completed`；实验草案状态与 Test 分开，另保留 `blocked`、`failed`、`cancelled`。`budget_exhausted` 记录为停止研究的原因；env 继续到原定终点、且质量与成本合格时仍可完成正式评分。

已确认的有效性政策：被 env 正确拒绝的普通计划错误只记为指令/阶段结果，不自动将整次测试置为 failed；此前已接收指令继续执行，完整期间合格时照常计分，拒绝与修正次数另作诊断。必要数据缺失、信息泄漏、账本损坏和基础设施故障不适用这一规则。

已确认的比较政策：同条件已有的完整合格基线测试可以通过原记录身份被新比较引用，不启动新 Episode，不增加重复样本数，累计成本按实际执行身份去重。新的独立重复运行必须实际执行；正式比较样本预先固定，不从历史记录挑选最高成绩。

已确认的选择政策：候选满足预设晋级条件后由 experiment 自动更新实验基线；提交选择时核对当前基线与比较对手身份，已变化则重新比较，保留所有选择事件。不替换运行中的 Episode 版本或业务 LAgent 配置；自动生成候选仍属于下一阶段。

已确认的运行缺陷政策：明确属于候选自身的程序崩溃，在配置的阶段内恢复耗尽后结束该阶段，下一预定阶段可用同版本和最后提交状态继续，env 保留并执行已接收指令；完整期间质量与成本合格时按实际收益计分。服务/平台故障、数据质量问题和无法归因的异常不自动套用此政策。

| 记录 | 最少保留内容 |
| --- | --- |
| 实验定义 | 原始与生效配置、字段来源、规则/数据/价格表版本、配置哈希、实际日期和阶段列表 |
| 候选版本 | 父版本、实现与提示词产物、配置差异、分叉假设、提交来源和内容哈希 |
| 测试运行 | 候选/任务/重复身份、阶段状态、停止原因、预算账、账户结果、有效性与评分引用 |
| 阶段研究 | 信息截点、主/子任务关系、模型尝试、可观察输入输出、usage、费用、错误和研究产物 |
| 数据查询 | 查询内容、日期条件、搜索信任政策、时间语义、返回来源及内容引用、质量状态 |
| 模拟执行 | 计划回执、旧单/撤单/新单关联、成交证据与模型版本、累计成交、资源冻结/释放、执行失败原因 |
| 比较与选择 | 确切测试记录列表、权重、聚合规则、基线/候选差异、晋级规则、选择理由 |

事件同时区分实际记录时间和模拟生效时间。失败、受阻、取消、重跑和恢复尝试全部保留；恢复追加同次记录，重跑生成关联的新记录，修订/重新评分不覆盖原结果。

进化树从上述记录生成视图：候选是节点，父版本和分叉假设形成边，所有测试挂在对应节点下。淘汰节点仍可作为新分支父节点；比较对象是当前基线，不能只因战胜旧父版本就晋级。

必要审计记录写入失败时不能无记录地继续产生新副作用；持久化、幂等和恢复必须覆盖撤单释放、新单提交和成本结算。外部原始数据是否仍可下载按其自身保留政策记录，不把永久留存测试记录误写成永久持有所有外部原文。

## CLI / skill 影响检查

本轮仅同步设计契约，不新增运行能力、API、配置入口或命令，因此无需修改 CLI catalog 和 ahunter skill。实现时必须同步 CLI/API/skill，并完成维护检查及仓库要求的代码验证。
