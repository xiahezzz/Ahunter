## 两层优化与独立评测

| 对象 | 本项目拟议映射 | 每轮保留的产物 |
| --- | --- | --- |
| 任务解法 | 在盘前和盘后窗口基于当时可见信息形成并调整的研究判断、交易计划和模拟决策 | 有证据的计划、委托、成交与账户轨迹 |
| 内层 LAgent | 固定版本的一个主 agent 跨窗口研究任务，可在允许窗口委托任意研究子任务，利用已发生的反馈调整后续计划 | 研究与决策轨迹、任务内记忆、结束时的评测记录 |
| 外层优化者 | 修改内层 LAgent 的提示词、上下文组织、候选搜索、委托和执行实现 | LAgent 实现与配置的不可变版本 |
| 独立评测器 | 提供历史环境、数据访问、模拟成交、评分和成本计量 | 带证据的评测记录和版本比较 |

第一阶段已确认实现内层的盘前研究、挂单、盘中环境撮合与盘后复盘闭环、候选版本对比及进化树，为后续自动外层提供统一契约。现有 LAgent 的 data/query/delegate/finish 行为可以复用，但还缺少决策窗口、模拟时钟、跨时点账户状态和模拟委托契约。

这里沿用文章的两层优化关系，但交易任务的解法表现为跨日的盘前计划与盘后复盘过程，不强制内层先生成一个独立策略程序再提交评分。不能把这种领域映射描述成逐项复刻原文的代码优化实验；公开/隐藏评测及等成本比较原则仍适用。

## 模块划分草案

用户提出的外层模块是 ahunter CLI、budget、env、evaluate。“外层平台”对应 LAgent Experiment Platform，“外层优化器”对应 LAgent Outer Optimizer；两者的职责及可修改范围已确认，以下模块清单和具体 Interface 仍是设计草案。

这是逻辑模块划分，不要求每个模块成为独立进程或新服务。沿用本地单用户部署及已有 CLI/API、持久化任务基础；现有基础尚未提供下列实验接口。

### 外层平台：提供并执行实验规则

| 模块 | 独占职责 | 对外 Interface 草案 |
| --- | --- | --- |
| `ahunter CLI` | 提交实验配置、查看/取消运行、读取比较结果；复用 HTTP 客户端入口 | 提交、状态、取消、结果；不承载模拟和评分逻辑 |
| `experiment` | 固定配置及所有版本、管理任务生命周期和预定决策窗口、安排基线与候选评测、保存产物引用 | 提交实验、按固定阶段推进运行、获取实验记录 |
| `budget` | 按统一价格版本预留和结算模型/计算等研究资源成本、执行预算停止政策 | 预留、结算、查询研究预算余额；原子处理并发委托 |
| `env` | 模拟时钟、历史数据/搜索可见性、沪深 A 股范围、可配置账户规则与资金持仓、DAY 限价单/撤单/受限撤换的校验与执行 | 建立独立环境、在决策阶段观察/查询与接收计划、由平台推进行情和撮合 |
| `evaluate` | 组织公开/隐藏/最终留出任务，验证运行有效性、计算收益和比较结果 | 评测一个 LAgent Episode、比较 LAgent 版本；按调用者角色返回允许的反馈 |
| `runtime` | 在预定决策窗口隔离执行模型和候选代码，管理任务进程、取消和崩溃回收，并将实际调用纳入预算 | 执行受限工作、取消工作；禁止窗口外模型执行，隐藏凭据、原始数据和宿主权限 |
| `trace` | 持久保存模型尝试、数据证据、候选差异、成本、环境事件、评分及晋级依据 | 记录事件、查询授权视图和产物；区分操作者与 agent 可见内容 |

`experiment` 是已有任务能力的实验扩展，不再另建与其争抢任务所有权的执行器。CLI 为人和自动优化者提供入口，业务规则只实现一次。配置由实验记录统一固定，各模块验证并拥有自身参数语义；“全部可配置”不意味着被测 agent 可以更改实验规则。

### env 的内部模块与 Interface（草案）

env 作为一个对外模块，内部按事实和状态归属拆成五项职责，不增加五个独立进程。所有调用都通过同一个 Episode 的 env，不能让内层拼装自己的账户、行情与成交规则。

| 内部模块 | 拥有的行为与事实 | 主要配置 |
| --- | --- | --- |
| `clock` | 模拟时间、盘前/非决策/盘后阶段及当前信息截点；只有平台推进时间 | 时区、预定窗口、窗口内时间推进及截止政策；当前实验禁止唤醒 |
| `data` | 按截点和权限提供历史行情、公告、MX 及搜索证据，验证历史内容可用性 | 已配置的数据产品、数据版本、允许来源、质量与历史可见性政策 |
| `market_rules` | 历史证券范围及状态、交易日历、委托合法性、价格/数量约束与交易费用规则 | 沪深 A 股范围、适用市场规则版本、费率及其历史生效区间 |
| `account` | 初始状态、资金制度、现金和持仓预留/释放、净值及适用债务结算 | initial_state、policy；资金制度可配置 |
| `execution` | 盘前计划接收、证据驱动的成交、撤单/受限撤换、部分成交及日末失效 | 指令契约、成交模型、时序/流动性参数、所需证据级别及处理政策 |

`market_rules` 决定市场规则下指令是否有效、费用如何计算；`account` 根据资金制度判断是否有足够购买力或可卖持仓并维护账本；`execution` 决定已接受委托是否能在相应时点成交。execution 不自行维护第二套现金余额，account 不根据盈亏反推成交。

`data` 分开提供 agent 在当前窗口可见的证据和 env 撮合时需要的市场事件。平台可以按顺序读盘中行情计算成交，但不得将这些内部事件通过查询、日志或观察对象提前暴露给盘前 agent；结果在下一允许窗口才进入其上下文。

对外 Interface 草案保持以下五种操作，名称不是已经存在的 API 或 CLI 命令：

| 操作 | 调用者 | 必须维持的约束 |
| --- | --- | --- |
| 建立 Episode | experiment / evaluate | 固定完整配置和数据版本，建立独立账户，不继承其他候选的记忆 |
| 查看当前状态 | 内层 LAgent | 仅返回允许窗口的时钟、可见持仓/资金/回执、账户政策及必要交易规则 |
| 查询证据 | 内层 LAgent | 强制绑定 Episode 及当前信息截点；子任务使用同样约束 |
| 提交盘前计划 | 内层主 agent | 校验窗口、委托类型、证券范围和资金/持仓，产生可追溯的接受或拒绝回执 |
| 结束并推进阶段 | experiment / evaluate | 结束 agent 执行后推进环境撮合和结算；agent 只能声明本窗口完成，不能指定盘中观察时刻 |

状态查询和提交计划的副作用必须可复核。同一逻辑委托的通信重试不应重复挂单或重复冻结，部分成交和日末失效只落账一次；每次状态变化关联到委托、证据、规则版本和账户变更记录。已确认每阶段计划整份校验与接收，拒绝后可在该阶段预算内修正；具体指令排序、资源竞争和恢复身份仍需细化，见独立 Interface 草案。

创建实验时验证所选配置与数据能力是否匹配。普通未成交、非法委托和证据缺失分别记录：前者是有效市场结果，非法委托有明确拒绝原因；需要的证据缺失是质量问题，不能自动改成普通未成交或伪造成交。evaluate 决定质量问题导致的评测有效性，不能静默丢掉失败案例再排名。

### 资金制度的模块归属

资金制度由 `env` 内部的账户模块拥有，建议配置入口为 `env.account`。它决定一笔模拟委托能否使用资金或持仓，并在委托接受、成交、到期及结算时维护账户；不另建顶层资金管理服务，也不把这套规则放进内层 LAgent。

区分三个概念：账户规则是本次选择的资金制度，初始账户是 Episode 开始时的余额和持仓，账户状态是运行中不断变化的现金、冻结金额、可卖数量及适用债务。初始资金 20 万元属于初始账户，不能据此推导或锁定资金制度。

| 模块 | 与资金制度的关系 |
| --- | --- |
| `env.account` | 拥有配置含义及合法性校验；执行可用资金/持仓、预留、扣减、释放、结算及适用借贷规则，维护唯一模拟账户账本 |
| `experiment` | 保存并固定 env 配置及规则版本；同组候选使用同一资金制度和初始账户，改变它们产生新实验定义 |
| `budget` | 只计量研究资源支出；不持有交易本金、不冻结买单资金、不处理交易手续费 |
| `evaluate` | 读取 env 提供的账户净值和交易费用事实计算收益，不重复实现资金制度 |
| `trace` | 记录规则版本、委托关联及资金/持仓变化，解释为何接受、拒绝、冻结或释放 |
| `ahunter CLI` | 提交和展示 env.account 配置及可见账户状态；规则校验和执行留在 env |

配置结构草案：`env.account.initial_state` 保存币种、初始现金和初始持仓，`env.account.policy` 保存选定的资金制度及其版本和参数。政策可表达账户模式、融资/融券是否允许及额度、适用保证金/利息/借券条件、资金与持仓的可用规则；字段集合和受支持模式应由实际实现能力决定，不把本列表当作已经实现的接口。

交易市场自身的规则、费率和成交证据归 env 的相应规则模块，账户模块根据这些版本化规则落账；不允许账户选项暗中覆盖已固定的交易范围和当日限价单约束。资金制度若需要自动风险处置，其执行同样必须有预先确定的规则；与禁止盘中 agent 决策、首版委托能力不兼容的组合应在实验创建时明确拒绝。

配置引用在实验接受时解析为完整快照及版本/哈希。LAgent 只读取当次政策和当前账户状态，并在允许范围内决策；不能修改政策、直接写账本或自行抬高额度。尚未支持或缺少必要数据的制度明确拒绝，不能悄悄降级为现金账户。

交易本金与研究成本是两份账：股票买卖、交易费用及适用融资成本影响 env 账户净值；模型调用和计算消耗 budget。研究支出单独报告，不默认从 20 万元本金扣减，也不暗中改变收益率评分口径。

操作者使用完整 ahunter CLI；内层若经 CLI 调用数据产品，只获得绑定当前实验和模拟时钟的受限命令入口，最终仍由 env 检查。不能把拥有实时查询、配置修改或隐藏报告读取能力的完整宿主 CLI 直接交给内层，也不依靠 agent 自觉附带正确日期来防止越界。

`env` 负责“发生了什么”：例如涨停买入请求是否成交、成交多少。`evaluate` 负责“表现如何”：基于独立环境账本计算净收益并验证该次运行是否可比较。评分模块不重写成交结果，环境模块不按得分反推成交。

`evaluate` 隐藏任务清单和分数，不把整个任务集交给内层；执行隐藏任务时只提供当前实例允许的环境访问。公开评测也由同一个环境实现负责逐时点约束，避免开发和验证采用两套成交逻辑。

`runtime` 对模型调用、代码执行和子任务实际操作实施约束，`budget` 提供唯一成本账本。内层可以决定花钱研究什么，不能绕过计量自行启动无限制进程、网络或模型客户端。价格版本、缓存费用、免费但消耗计算资源的操作以及执行前成本预留政策需要在具体预算设计时定义。

### 外层优化器：改进内层 LAgent

`optimizer` 读取允许的汇总反馈，提出 LAgent 实现/配置补丁，交由平台封存候选并评测；依据固定的晋级规则选择保留版本。它是外层 loop 的决策者，不是 budget、env 或 evaluate 的拥有者。

已确认它仅能修改候选包中的内层实现与允许调优的配置。实验定义、预算上限、隐藏数据、成交模型、评分函数、执行隔离和审计规则保持只读。若确需修改平台，由操作者另建实验版本并重跑基线。自动优化能力可以后接，不能用“外层模块已经存在”声称外层 loop 已运行。

内层配置也分为可调优字段和实验固定条件：提示词、上下文组织、搜索和委托策略可以作为候选变化；本次指定的 GPT-5.5 high、数据权限及预算政策仍由实验固定，不能通过修改候选配置绕过。

### 内层：固定版本的 LAgent 优化任务解法

| 模块 | 自主决策 | 交给平台执行的行为 |
| --- | --- | --- |
| `main` | 唯一主 agent 在允许窗口决定研究目标、盘前计划与委托、盘后复盘 | 数据访问、模型调用、提交盘前计划及模拟委托、结束本窗口 |
| `search` | 探索和比较研究假设、标的及交易计划，决定深入、修正或放弃 | 数据查询、允许的历史检验、证据记录 |
| `context` | 为主 agent 和各子任务组织已允许的信息、记忆和反馈 | 读取受限的证据及历史视图 |
| `delegate` | 自主定义子任务、选择委托方式并整合结果 | 经 runtime 启动任务，经 budget 计费，经 trace 留痕 |

上述模块是可替换的内层实现职责，不是强制先后执行的固定研究流水线；主 agent 可在允许窗口按任务选择动作。数据产品与搜索通过 env 提供，内层可以自由选择当前实验允许的产品，不能直接读未过滤的数据库或网页，也不能订阅事件唤醒或申请盘中观察。

内层产物是研究判断及模拟决策轨迹，不要求独立的可执行策略包。外层维护候选 LAgent 版本谱系，内层保留研究假设和计划的演变记录，两者分别归属和观察；`search` 在这里指研究方案探索，不指平台网页搜索接口。

### 已确认：固定 LAgent 版本，跨决策窗口保留状态

一次 LAgent Evaluation Episode 使用封存的代码、提示词模板、配置及依赖，在盘前和盘后决策窗口可通过 runtime 调用指定模型并委托研究，以处理 env 在该窗口模拟时点提供的信息。每个 Episode 维持一个主决策者，子任务只返回研究结果；研究调用、重试和计算纳入同一任务预算。

可变化的是持仓、已见证据、任务记忆、研究计划和具体决策；封存的 LAgent 实现与配置保持不变。动态组织上下文、生成子任务指令是该版本的正常运行行为，不等于改写提示词模板或研究程序。成交回执和账户盈亏由环境留存，等到下一预定决策阶段才交给 LAgent：开盘竞价成交可在竞价后盘前阶段读取，09:30 起的执行结果等到盘后窗口；完整隐藏区间分数、其他候选的隐藏表现和跨实例记忆不能进入当前 Episode，下一次独立评测从干净状态启动。

例如 08-04 10:00 发布公告，平台不会唤醒主 agent 或 subagent，也不允许它们修改当日委托。公告可在 08-04 23:00 之后的复盘窗口被研究，结果用于后续盘前计划；optimizer 不能改写当前运行版本或让它回到 08-04 早盘重做决策。

### 已确认：盘前计划、盘中环境执行、盘后复盘

| 阶段 | LAgent 行为 | 平台行为 |
| --- | --- | --- |
| 盘前竞价前：最终开盘竞价结果产生之前 | 基于较早快照研究并提交参与开盘竞价的买入、卖出计划；也可选择不挂单 | 校验整份计划，按历史申报规则接收委托并由 env 撮合开盘竞价 |
| 盘前竞价后：结果及回执可见，模拟时间严格早于 09:30 | 读取最终竞价结果、自己的成交回执和更新账户；使用可用净回款形成下一份计划 | 冻结新的阶段快照并校验计划；竞价后新委托不回填至开盘竞价 |
| 09:30 至 23:00 的非决策阶段 | 主 agent 和 subagent 均不运行；不接收事件唤醒，不新增、撤销或修改委托 | env 仅按预提交指令和交易规则推进、撮合及留存结果；runtime 不调用模型 |
| 盘后：模拟时间严格晚于 23:00 | 复盘当日计划和成交、研究截至复盘时刻的信息、保留记忆并形成后续计划 | 提供届时可见的账本、证据和执行结果；不得追改当日成交 |

09:30 和 23:00 本身不属于允许决策窗口，时间使用 Asia/Shanghai。盘前分为两个预定阶段，每个阶段独立固定信息截点，现实研究耗时不推动模拟时钟；只有竞价后阶段包含已公开的最终开盘竞价结果。具体快照/提交时刻和盘后启动时刻由实验配置解析，不会把“23:00 后”擅自写成恰好 23:00 运行。

每笔模拟委托必须分别保留现实提交时间、模拟平台接收时间及交易所申报接受/撮合资格时间，不能把 09:30 前提交的委托倒填为更早已参与撮合，也不能用后来发生的当日行情修改盘前计划。委托类型和有效期已确定为当日有效普通限价单；当前在最终开盘竞价结果公布后形成的新委托不参与当日开盘集合竞价。主 agent 的解释性计划文本本身不会被盘中模型翻译成新动作。

首版支持普通 DAY 限价单、盘前预提交撤单及参数在盘前固定的受限自动撤换。env 可在盘中推进这些已经接收的流程，不能根据盘中行情重新选择价格、目标数量或证券；不支持通用条件单、止损触发单或任意策略代码驱动的盘中操作，也不能将自然语言“视情况处理”作为绕过禁止盘中决策的入口。

主 agent、subagent、重试和延迟回调受同一窗口约束，不能通过后台子任务在非决策阶段继续研究。超出窗口的截止处理需要在 runtime 设计中确定；模型不得顺延到盘中补计划或补单。env 按盘前已接收的撤换流程提交预定新单属于执行既有指令，不重新开放决策窗口。

首个 Episode 仍在 08-02 启动；建议首次研究安排在该日 23:00 之后、午夜之前的允许窗口，具体启动时刻待确定，信息截点必须仍落在 08-02；随后进入 08-03 盘前。五个交易日按相同阶段推进，08-07 的盘后复盘不产生额外交易日，也不得改动该日已发生的模拟执行。

### 已确认：最终竞价结果公开后冻结盘前快照

用户已明确要包含 09:25 结束时的最终开盘竞价结果，采用结果实际公开后冻结信息快照、09:30 前提交计划的口径。09:25 是当前案例中的竞价结束时刻，仍通过配置和历史市场规则表达；信息可见性必须依据实际发布时间核验，不能将其简化为严格早于 09:25。

历史回放采用固定阶段快照：盘前竞价前、盘前竞价后和盘后各绑定一个信息截点，主 agent 和全部 subagent 在同一阶段始终读取截至该点可见的信息。阶段转换由平台按实验预定流程推进，不是成交事件唤醒，也不允许 agent 自选观察时刻；没有卖单成交也按预定流程进入竞价后阶段。现实中的模型等待、重试、数据查询和机器负载不推动模拟市场时间，分别记录实际耗时和费用，并由配置的预算及 runtime 超时限制。

这是一种测量固定信息条件下研究与决策能力的历史回放政策，不宣称模型在真实交易当天能按同样速度完成研究。若未来要测实际响应速度，应另设耗时推动模拟时间的实验政策，并重新固定比较条件；本轮未将该模式加入首版。

| 时间或限制 | 含义 | 所属 |
| --- | --- | --- |
| 阶段信息截点 | agent 在当前预定阶段能看到的最晚信息时间，阶段内不更新 | env.clock，env.data 强制执行 |
| 盘前计划提交时刻 | 模拟平台接收计划和待报限价委托的时刻，须在允许决策窗口内 | env.clock 配置，runtime / env.execution 校验 |
| 交易所申报接受及撮合资格时刻 | 按历史市场规则接受申报、获得撮合资格的时刻，不能等同于平台接收计划 | env.market_rules / env.execution 执行 |
| 现实执行时刻/耗时 | 这次研究实际何时开始、执行多久 | runtime 计量、trace 记录 |
| 现实超时与费用上限 | 允许研究消耗的现实执行时间和资源 | runtime / budget 执行 |

根据测试期间适用的 [上交所 2026 年交易规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)及[深交所 2026 年交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/W020260424690713155663.pdf)，开盘集合竞价为 09:15–09:25，连续竞价从 09:30 开始；竞价交易申报接受时段不包含 09:25–09:30 的间隔。观察最终竞价结果后新形成的委托不得倒回参与同一场开盘集合竞价。平台可以在 09:30 前接收计划并暂存待报委托，随后由 env 按规则申报，最早从 09:30 起取得撮合资格，不能据此保证成交。

平台接收计划与交易所接受申报是不同阶段，实际平台提交时刻按定稿 D03 的可配置预设，所有时刻均通过配置及市场规则共同校验。

竞价后阶段的端点口径：以 09:25 开盘集合竞价结束、最终结果已公开可见后的固定快照进行研究，快照与计划提交均严格早于 09:30。若结果实际在 09:25:00 之后公布，必须如实记录并配置更晚的信息截点，不得伪称在 09:25:00 已知，也不得仅凭行情标签为“09:25”提前放行。最终快照中的行情、公告、搜索结果等全部使用同一个信息可见性截点；自己的模拟成交回执也须满足配置的回执可见性规则。主 agent 与 subagent 不得自行推进截点，竞价前阶段不能读到竞价后快照。正式回放缺少可核验的发布时间或历史竞价证据时，按数据质量规则处理。

信息截点不得晚于相关决策/委托生效时刻，二者均须满足实验选定的窗口和市场规则。精确时刻、端点语义和已支持的执行模式在创建实验时校验，不按机器运行速度临时调整。盘后复盘同样冻结信息截点；模型实际执行跨过现实午夜不意味着模拟 08-02 的复盘可以读取模拟 08-03 的信息。

在这个政策下，窗口关闭是 experiment 在本窗口工作完成、超时、取消或预算终止后发出的阶段变化，不是用宿主机当前几点来决定是否处于盘中。关闭前先停止或收回主/子任务权限，迟到回调不能提交计划；关闭后仅平台推进环境，仍满足禁止盘中 agent 执行的要求。

当前 LAgent 的每次请求已有固定 Research Boundary，适合复用为单窗口证据截点；连续 Episode 需要按预定窗口建立新的截点并带入合法的历史任务状态。不能把已有单请求边界当作完整的多日回放时钟，也不能把业务模式的即时行情预取直接套入历史窗口。

该时间政策已确认，见 ADR-0107；后续委托批次及预检/接受语义以固定信息视图和分别记录的平台接收、交易所接受时刻为基础细化。此处是设计约定，尚未改变当前运行行为。

### 已确认：盘前计划整批校验与接收

主 agent 在每个盘前阶段提交该阶段完整计划，由 env 在阶段冻结快照及当前账户状态下校验整批限价委托；若发现任一委托不合法或整批所需资金/持仓不满足所选账户规则，整份计划退回，不先接收其中一部分。校验全部通过才一次接收并按账户规则预留资源，平台不自行删单、缩量或重排投资意图。校验失败不留下部分委托或部分资源冻结；竞价后计划被拒绝不回滚此前已接受的竞价前委托或已发生的成交，后续校验必须计入前一阶段尚未释放的资源占用。

拒绝回执逐项说明可由当前可见证据判定的问题。只在本次盘前窗口仍开放、研究预算与配置的修正次数/超时允许时，主 agent 才能依据同一快照修正重提；窗口结束后不得补单。每次提交、拒绝和修正关联到版本及测试记录，通信重试沿用同一提交标识，避免重复接收。

这里的整批接收只决定平台是否接纳计划，不保证所有委托成交或同时成交；之后仍可能分别被市场拒绝、部分成交或到期未成交，不能因其中一笔失败撤销另一笔已发生的成交。平台校验不得查询信息截点后的行情、停牌变化或成交结果来提前指导 LAgent。正式执行证据缺失仍是质量问题，不应包装成普通计划错误供 agent 反复试探。

### 已确认：不预支回款，允许竞价卖出后重新挂单

整批校验仅使用提交时依所选账户政策已可用的现金与信用额度，并预留适用费用，不将尚未成交卖单的预计回款当作已经可用的资金。允许开盘竞价卖出实际成交后，在竞价后阶段使用扣除适用费用且按账户政策已经可用的净回款重新制定并提交买单；这属于已成交资金的使用，不是对未来卖出的预支。此项由 env.account 定义和校验，env.execution 依据资源预留接收委托，experiment 固定政策快照；它不把可配置账户制度改成固定现金制度。

例如，账户没有可用信用额度，竞价前有 1 万元可用现金，提交约 10 万元的卖出计划；竞价仅成交 4 万元，则竞价后最多以原有可用现金加这 4 万元扣费并按账户政策确认可用后的金额安排买单，还需满足新买单费用预留。剩余未成交卖单不产生回款，仍按原 DAY 限价单及历史市场规则延续执行并占用对应可卖持仓，不因阶段转换自动撤销或复制。例中数值仅说明行为，不是参数默认值。

竞价前买卖单必须依据更早信息提交并在交易所历史规则允许的时段取得申报资格，不能看完最终竞价结果后倒填委托。竞价成交量、排队和流动性由 env 的历史证据及固定成交模型判定，不能将有开盘价当成必然买入或卖出；证据不足按质量规则处理，不伪造成交或回款。

竞价后重新挂单由同一主 agent 在预定阶段主动决定，仍不支持等待 09:30 后某笔卖单成交再唤醒模型或自动补发买单。两个盘前阶段共享 Episode 的研究预算与状态；trace 永久保留阶段截点、计划与委托身份、成交证据、回执可见时刻、费用、可用资金和持仓冻结变化。具体阶段时间、回执延迟、费用和成交参数均配置化，同组版本固定相同政策。

### 已确认：竞价前允许买入和卖出

竞价前允许买入和卖出，买单只能使用该阶段提交时已可用的资金或信用额度，不依赖同阶段预计卖出回款，并遵守同样的可交易持仓、信息截点、整批接收和成交证据规则；不得因此扩大已经固定的市场、账户权限或委托类型。未成交买单继续占用按账户规则冻结的资金，部分成交只释放或扣减规则允许的对应金额；竞价后新计划不能重复使用仍被旧单占用的资金或持仓，竞价买入的证券能否卖出仍由历史市场及账户规则判断。

### 已确认：竞价后预提交撤单

允许主 agent 在竞价后、09:30 前的固定阶段，对竞价遗留委托的未成交部分提交撤单指令。普通 DAY 委托不会因为看过竞价结果或生成新计划就自动撤销；若主 agent 没有提交撤单，继续按原委托及市场规则执行。

平台接收撤单请求不等于交易所撤单成功。按上文引用的历史申报时段，09:25–09:30 期间暂存的请求只能在恢复接受申报后由 env 提交；确认前仍冻结旧单资源，并保留原委托继续成交的可能。撮合与撤单竞争按固定执行模型、时序证据和配置延迟处理，不能保证撤单抢在成交之前，也不能回滚此前成交。

这一规则只允许盘前决定、随后由 env 执行的撤单，不新增盘中模型判断。竞价后独立的新买卖单仍须用提交时已经可用的资源通过整批校验，不预支待撤委托尚未释放的资金或持仓；依赖撤单确认的替换单按下述已确认流程另行处理。若本阶段计划包含撤单和新单，整批接收仅保证平台一致接收指令，不意味着交易所原子撤换或撤单必成。

env.execution 维护撤单请求与原委托的关联、待提交/待确认及最终结果；env.account 只按已经确认的撤销数量释放资源，已成交部分按成交落账。原委托全部先成交时撤单无剩余可撤，部分先成交时只能撤剩余部分；重试不重复撤销或释放。trace 永久保留请求、提交和确认时间、竞态期间成交、撤单失败或无剩余的原因，以及对应规则版本。盘中这些回执只供平台执行，主 agent 在下一允许阶段才读取。

### 已确认：撤单确认后自动重挂

首版开放受限撤换流程：主 agent 必须在竞价后、09:30 前预先指定要撤的旧单、新限价以及原单与新单合计的目标成交数量；新单保持同证券、同方向。env 仅在旧单剩余部分撤销确认后，根据既定目标减去旧单累计成交量计算新单数量，并在资源校验通过后提交普通 DAY 限价单，既定价格不能根据盘中行情重新选择。目标已经完成则不再挂单；撤销失败或资源不足则记录原因，不自动缩量、换价或调用模型。

此项是已确认的首版执行契约扩展，尚未实现。整批接收只表示接受预定撤换流程，依赖的新单在撤单确认及资源再次校验前不能被标记为已接受的交易所委托，也不得提前冻结同一份尚被旧单占用的资源。具体排队时序、超时和操作身份由固定配置及执行模型约束，不能保证撤换成功。此项不开放根据股价、新闻或新卖出回款触发的通用条件单，也不支持盘中模型决策。

env.execution 拥有旧单、撤单请求、撤换流程和新单之间的稳定关联，env.account 在撤单确认与新单资源校验时维护一致账本；trace 记录既定参数、期间成交、新单数量计算依据、资源检查、提交及未执行原因。重复回执或恢复重试不得重复释放资源或重复挂出新单；同一旧单的相互冲突撤销/撤换请求须在整份计划校验时拒绝。新单申报时还须满足历史交易规则、数量单位、价格范围及有效期，不能用撤换绕过校验；不合法时保留明确结果，不由平台擅改参数。

研究预算耗尽后，已经接收的撤换流程与已有委托一样由 env 继续按原计划执行，费用使用任务内预留的环境执行资源；未接收的模型草稿不能补入。新单保持当日有效，不续到下一交易日；测试记录分别保存流程被接收、撤单确认、新单校验/申报和最终成交结果，不能将计划接收记作撤换成功。

### 已确认：固定历史行情路径，不模拟订单对后续走势的影响

首版采用固定历史行情路径：所有候选面对同一份历史行情，模拟委托不反向改写后续市场价格和其他参与者行为；按预先固定的成交模型加入委托时序、可用流动性、参与量限制、排队假设和滑点，并按账户规则扣费。模型及全部参数归 env.execution / env.market_rules 配置，experiment 固定快照，evaluate 只读取执行结果评分。这里的滑点仅影响模拟委托的成交估计且须符合限价约束，不据此改写之后的历史行情。

这一方案明确假定模拟交易没有改变后续市场路径，不能据此声称评估了大额订单的真实市场影响。不同订单共同消耗同一时段的可用成交容量，撤换不能重置已消耗容量或继承不应继承的排队优先级；新单只能使用其实际取得撮合资格之后的机会。量能上限只是约束，不是成交证明：涨跌停排队、开盘竞价和撤单竞态等仍须满足各自证据要求，缺少关键证据按质量规则处理，不把价格触及直接算作成交。

### 一次完整调用

操作者或 optimizer 通过 ahunter CLI 提交候选 LAgent → experiment 固定版本、预算政策和决策阶段 → evaluate 安排 Episode → runtime 运行初始盘后研究 → 竞价前阶段提交计划 → env 推进开盘竞价 → runtime 在预定竞价后阶段提供新快照及可见回执，LAgent 提交新计划 → 结束盘前窗口，env 推进后续撮合 → 23:00 后 runtime 运行盘后复盘 → 下一交易日继续 → Episode 结束后 evaluate 独立评分 → experiment 保存比较结果。

budget 覆盖整条执行路径；trace 留存各模块事实。optimizer 只能取得本次实验允许的选择反馈，不通过 trace 获得隐藏测试答案。未参与调优的最终留出任务不提供优化反馈。

### 检查模块划分的场景

- LAgent 盘前提交的买入委托在当日遇到涨停：env 按证据决定是否成交，evaluate 据此计分；不得临时调用 agent 决定是否追涨。
- LAgent 同时委托多个任务：delegate 决定研究内容，runtime 执行，budget 原子预留并结算共同额度。
- optimizer 尝试把无法成交改为成交，或抬高预算：平台拒绝修改；不能作为同一实验的有效 LAgent 候选。
- 候选崩溃或被取消：runtime 停止，budget 结算已发生消耗，trace 保留事实，evaluate 标记有效性，experiment 结束对应运行。
- 操作者调整手续费或隐藏任务集：产生新的实验配置版本，旧分数不直接混入新版本排名。
- 盘中公告或价格事件发生：env 可以留存事实，但不得启动主 agent 或 subagent；只在下一允许窗口提供已公开信息。

## 内层一次任务

1. 固定任务定义、资金、规则、模型、LAgent 版本、资源政策和决策窗口，建立初始时点和独立账户。
2. 在允许的盘后或盘前阶段，主 agent 调用数据产品或委托研究；竞价前计划执行开盘竞价后，在预定竞价后阶段读取结果与可用回款，再提交新计划，全部决策严格早于 09:30。
3. 结束盘前窗口，停止 agent 执行；env 独立推进当日行情并撮合预提交委托。
4. 23:00 后主 agent 根据已发生的账户反馈和届时可见的信息复盘，保留记忆，在后续盘前窗口完成下一交易日计划；实现与配置不变。
5. 到达任务终点或其他停止条件后，evaluate 基于完整轨迹计算结果；只向相应调用者提供允许的公开或隐藏评测反馈。

不把文章演化出的复杂候选代码搜索算法直接写成内层强制流程。一次模型调用、一次决策、一天行情推进与一次完整 Episode 是不同事件。

## 时间与反馈边界

先将两个时间概念分开：调优可使用的公开任务范围，以及每个 Episode 内的模拟时钟。公开任务也必须逐时点执行，不能以完整区间行情直接产生较早时点的决策。

- 公开开发集：可反复运行和分析反馈以改进 LAgent；每次运行内仍只能使用其模拟时点可见的信息。内层若检验历史假设，也仅能在当时已公开的历史范围内进行。
- 隐藏验证集：独立评测器安排 Episode，只向 LAgent 提供当前时点可见信息；外层如用其汇总分选择版本，它便属于调优反馈，不能再当最终盲测。
- 最终留出任务：冻结 LAgent 版本后评测，不参与策略或 LAgent 版本选择；同时覆盖未参与调优的时期与市场条件。

2026-08-03 至 08-07 已确认为首个开发/调优基准任务，用于反复测试、比较分支并完善 LAgent；最终留出评测另选未参与调优的期间，预留日期及暴露检查按定稿 D10 执行。原始研究启动日仍为 08-02，交易期和每个阶段的信息截止规则保持不变。

### 已确认：原定五日任务作为调优基准

| 任务角色 | 对改进 LAgent 提供的反馈 | 是否进入版本选择 |
| --- | --- | --- |
| 开发/调优任务 | 可反复查看研究轨迹、执行失败、收益及成本，形成分叉假设 | 定稿 D10：用于产生候选；不混入正式验证晋级分 |
| 用于选择的隐藏验证任务 | 内层逐阶段执行；外层只取得配置允许的验证反馈 | 可以，但一旦用于选择就属于调优反馈，不再称最终盲测 |
| 最终留出任务 | 候选冻结后评测，结果不回流到当前版本的调优过程 | 不进入当前候选晋级分数 |

原定 08-03 至 08-07 作为开发/调优任务，第一阶段手工提交候选时可检查每次失败和改进，并在进化树中明确标记这一角色。最终留出预设及 exposure 政策已在定稿 D10 选择；正式留出尚未运行时，可以展示调优基准成绩，但不能声称已验证未见期间的表现。

任务角色由 evaluate.suite 定义，experiment 固定任务身份与角色历史；trace 记录哪些结果在何时被操作者或 optimizer 用于改进。曾用于调优的期间不能仅改个字段就重新变成未见留出集。人可以审计所有保留记录，但若据最终留出结果继续改进，后续必须将该期间标为已参与调优并为新版本另设留出任务。

这里的调优反馈属于外层；每次 Episode 仍从该任务的干净初始状态出发，env 不向盘前主/子 agent 提供未来阶段的结果、其他候选轨迹或完整区间成绩。允许外层反复看分数不等于允许内层越过当时的信息截点；同一期间的提升也不作为跨市场条件泛化的证据。

隐藏评测中 env 随模拟时钟更新持仓并留存已发生的信息，只在允许的盘前/盘后窗口向 LAgent 提供届时可见内容；LAgent 不能看到未来行情、其他候选在该区间的表现或完整区间分数。验证中的模型调用和委托同样经过窗口及数据边界并计入资源使用。

数据记录区分事件时间、首次公开时间、版本/修订时间与实际采集时间，不能伪造采集时间或把历史交易日期等同于内容当时完整可用。web 搜索采用用户选择的服务时间过滤信任政策，替代此前草案要求的逐页历史版本验证；自有数据仍须通过各产品的时间语义和阶段可见性规则。搜索请求、返回内容和缓存关联到同一阶段截点及生效信任政策，不能以缓存绕过查询截止条件。

上述隔离能控制工具提供的信息，不能证明模型训练记忆中不存在历史结果。评测报告应区分历史回放与前瞻验证，不能将工具时间过滤表述为完全消除泄漏。

### 已确认：只有发布日期的材料次日起可用

在来源只能提供发布日期、不能提供具体时刻时，以来源时区中该日期结束后的时刻作为最早放行边界：同日的盘前和盘后研究均不使用该材料，下一日期起才能通过这项时间检查。例如只有“08-03 发布”的材料不能进入 08-03 盘前快照；只有“08-02 发布”的材料也不直接放进 08-02 23:00 后但午夜前的首次研究。若来源能提供更精确的公开时间，可按实际时间处理，但不改写已完成的测试记录。

日期粒度与时区处理归 env.data，生效政策由 experiment 固定，trace 保存来源声明、时间精度、时区语义、信任政策、推导边界及拒绝原因。web 搜索按服务声明的日期筛选语义处理，不逐页追加档案证明；自有数据的产品时间语义和质量检查继续生效。服务时区或端点含义不支持精确映射时，适配器须采取不晚于阶段截点的保守范围，不能默认为秒级过滤已实现。

平台先落实截止筛选再向主 agent 或 subagent 返回标题、摘要、正文等内容。单条可选搜索材料因可见的超时信息或筛选错误被排除时留存记录；所需数据产品或任务的质量门槛未满足时，仍按既定规则阻断依赖研究及正式评分，不以空结果伪装为数据充分。验证规则、允许的时间精度和来源策略均版本化配置，但不能取消用户要求的历史截止条件。

### 已确认：信任 web 搜索服务的时间过滤

搜索截止条件由 env.data 从当前阶段截点自动生成，LAgent 选择查询内容及允许范围内的搜索参数，不能延后截止时间。首版信任所选服务的时间过滤结果，不自行建设逐页历史快照核验，不以缺少独立网页存档作为所有 web 结果的拒绝条件；报告应如实标明这一信任假设，不能声称已独立证明网页没有后续修订。

已核对的服务能力示例：[Google 官方说明](https://support.google.com/websearch/answer/2466433?hl=en)支持 before / after 日期操作符；[Tavily Search 文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)提供 YYYY-MM-DD 格式的 start_date / end_date，依据发布日期或最后更新日期过滤。它们说明可以配置日期范围，不证明当前 A Hunter 已集成服务，也不证明支持 09:25 级别的历史时间截点；此处没有选择、安装或采购任一服务。

服务只支持日期级筛选时，按照已确认政策，将搜索上界映射为阶段所在来源日期之前的完整日期范围，不把当日全部结果交给盘前阶段。同日精确到阶段截点的信息使用带足够时间精度的自有数据产品，或以后支持同等精度的搜索适配器。不能把“最近若干天”的相对当前日期筛选当作任意历史截止条件，也不能只在 prompt 中写截止时间而不发送服务支持的筛选参数。

服务、参数、过滤精度、端点/时区映射和信任策略由 experiment 固定。trace 保留实际查询、模拟截点、发送的日期条件、服务身份、返回来源及时间元数据、内容哈希与结果产物；原始来源的外部保留限制按既有政策记录。读取搜索命中的正文沿用该结果的服务信任假设，不额外要求独立历史版本证明；直接打开未经过筛选的任意网址不能冒充受截止条件约束的搜索结果。服务返回明确晚于截止日期的时间元数据时不能无视冲突，按过滤失败记录。

## 成交与评分

沿用用户要求：初始资金 200,000 元；2026-08-02 启动；交易期 08-03 至 08-07；GPT-5.5 high；收益率最大化；买入涨停股必须检验成交可能性。

### 已确认：沪深 A 股与当日有效限价单

交易范围为上海、深圳交易所的 A 股，明确排除北交所。按这个范围纳入沪深主板、科创板、创业板，不额外添加主板限定或 ST 排除条件；ETF、可转债、B 股等非 A 股证券不属于交易对象。这是交易范围限制，不能自动扩展为禁止研究有关市场或宏观证据。

股票池按照模拟日期重建，使用当时有效的证券身份、上市/退市及交易状态；不能用今天的存续名单替代历史股票池，也不能提前引入未来上市股票。停牌、涨跌停等状态由当时证据驱动的交易和成交规则处理，不能因为纳入范围就视为可买入。

现有 `advisor/market_daily/contracts.py` 的 `MarketSecurity` 已校验 SH/SZ 交易所和 `security_type=a_share`，并保留上市、退市、状态及 ST 字段；新浪股票池适配器也校验交易所符号和代码。实验应复用这些身份事实并校验历史可见性，不另靠股票名称猜测交易所。现有数据契约不等于历史数据和实验成交能力已就绪。

模拟账户的资金制度通过 env.account 配置，由 experiment 在每次实验中固定；板块权限和具体交易制度也须显式记录。不能仅凭初始资金 20 万元推断账户模式或权限，也不能据此擅自删除用户指定范围内的板块。

一笔委托包含证券身份、买卖方向、股数、限价和目标交易日；平台附加唯一身份、计划关联、提交/生效时刻和执行记录。类型固定为普通限价、有效期固定为目标交易日；字段及命令的具体命名留待 Interface 设计。

买入成交价格不得高于限价，卖出成交价格不得低于限价；价格满足只是必要条件，仍须独立校验可交易性和可执行流动性。env 可以记录部分成交，剩余未成交部分在目标交易日结束时失效，不自动延续至次日，也不会为提高分数改为市价执行。下一交易日是否重新挂单及其价格、数量由 LAgent 在下一盘前窗口重新决定。

普通限价不等于止损条件：例如低于当前价格的卖出限价表达最低可接受卖价，不能被解释为“跌到该价格才卖”。首版不增加未获授权的条件触发语义。

env 在接收委托时和执行时分别校验证券范围与适用规则；越界委托保留拒绝原因，不替换成其他股票。涨停能否成交、证据不足如何处理以及费用、申报单位、价格精度等规则待后续明确，不从“限价单”推导保证成交。

### 已确认：成交证据的最低数据要求

`env.execution` 的成交模型和所需数据级别一并配置、版本化。已确认正式普通限价单评测至少采用历史分钟行情建立按时间推进的成交模型；分钟价格和成交量仍只支持模拟估计，不证明反事实委托必然成交。限价触及、可用量分配、成交价格及费用需由同一模型明确规定，不能只要价格曾达到就全额成交。

涨停排队、临界触价或分钟内先后顺序等情形可能需要更细的逐笔或盘口证据，分钟数据不自动解除这些要求。若缺少当前模型要求的证据，应保留证据不足状态并阻断受影响的正式收益评分，不把未证实的执行包装成真实成交。具体模型和证据口径见定稿 D06。

现有产品目录包含日线和即时行情快照，尚未发现历史分钟或逐笔产品；不能把即时快照当作历史盘中路径。只使用日线可支持研究及明确标识的粗粒度模拟方案，但不能作为上述正式成交评测，也不与之混合排名。最低数据要求已确认，但当前尚未具备该能力；本决策不改变既有 Market Daily 的数据来源。

收益只能由独立模拟账本和成交证据计算，不能采信 agent 自报分数。LAgent 提交模拟操作意图，由 env 判定成交、部分成交或未成交，evaluate 根据这些事实评分；账本与真实交易记录隔离，不接券商。

涨停价格、日成交量或当日最低价本身不能证明决策之后该笔买入可成交。应按决策时间、可用盘口/逐笔/分钟证据及公开的成交模型判定；缺乏所需数据时保留未证实状态，按定稿 D06 区分模型 no_fill 与必要证据缺失，后者阻断正式计分。已确认的交易范围和委托类型，以及后续确定的交易制度、费用、流动性和期末估值政策，均在任务开始前固定。

主指标已确定采用含费用的期末净收益率，版本比较默认汇总固定任务集的平均期末净收益率，不将回撤或成本偷偷混入另一目标函数。回撤、换手和资源使用作为诊断；非法成交、越界证据、损坏数据或评测失败单列有效性，不静默删除坏结果。稳定性门槛和正式选择任务集见定稿 D10。

## evaluate 的内部模块与 Interface（草案）

evaluate 拥有评分与比较规则，通过 experiment 请求执行、通过 env 读取执行事实；不再维护第二套任务队列、模拟账本或成交逻辑。它内部划分以下四项职责：

| 内部模块 | 职责 | 主要配置 |
| --- | --- | --- |
| `suite` | 定义任务及公开/隐藏/最终留出划分，固定任务身份和反馈可见性 | 任务清单、时间区间、分组、重复运行要求、允许反馈 |
| `validity` | 检查数据和成交证据、窗口及信息边界、预算执行、账本和运行完整性 | 正式评测门槛、失败分类、哪些条件使一次评测不可计分 |
| `scoring` | 根据 env 的净值快照及执行事实计算主指标和诊断指标 | 计分时点、主指标、诊断项及相关政策引用 |
| `comparison` | 在相同任务、环境和成本条件下比较基线与候选，检查晋级条件 | 跨任务聚合、重复样本处理、比较阈值和晋级规则 |

对调用者只提供“评测指定版本”和“比较已完成评测”两类操作，返回可追踪的评测身份、状态、允许可见的指标及证据引用。suite 的任务定义由 experiment 快照固定，实际执行使用现有实验生命周期和 runtime，避免两边重复拥有调度权。

先检查有效性再计分。普通未成交及被 env 正确拒绝的普通计划错误均可作为实际运行表现计分；后者不能仅因未及时修正就把整次运行从比较中删除。必要数据缺失、已泄漏的越界信息、账本损坏等质量失败不能当作零收益样本或静默删掉；不完整评测不产生正式收益排名，且完整任务覆盖情况必须随比较结果一起展示。

正常达到成本预算停止与基础设施故障分别记录。预算耗尽后的环境推进、账户计价和最终可计分条件按已确认政策预先固定，不能在看到收益后才选择处理方式。多任务及重复运行默认使用已确认的平均汇总方法，不能以最高一次收益代表整个 LAgent 版本。

### 已确认：普通计划错误按实际运行结果计分

被平台正确拒绝的普通计划错误计为 LAgent 的运行表现，例如数量不合法、已有购买力不足或同一旧单指令冲突。窗口关闭前没有修正成功时，本阶段没有新接收的计划，env 仍执行此前已接受的委托/撤换并维持原有账户状态；下一预定阶段仍可继续研究，不能倒回补单。若完整期间的数据、执行、账本及成本均合格，照常按期末净收益率计分，并将这次运行纳入预定重复样本。

计划错误次数、拒绝原因、修正尝试及未成功提交的阶段单独作为诊断指标保留，不额外从收益率扣一个临时罚分，也不因这次表现差而自动重跑替换记录。主动选择不挂单仍是合法决策，与计划被拒绝分别记录；本阶段没有新计划不等于当日没有交易，先前已接受的竞价或连续交易委托可能继续成交。

此规则限于环境正确处理的普通计划拒绝，不将必要数据缺失、已泄漏的未来信息、账本损坏或基础设施故障归为投资决策失误。后者继续使用各自质量/失败政策；候选自身崩溃另按下述已确认规则处理，模型服务或平台故障不能混入候选缺陷。evaluate.validity 拥有分类及可计分条件，experiment 保存运行结果，trace 保留计划错误和其他失败的区别。

### 已确认：候选程序自身崩溃按实际运行结果计分

在有证据确认错误属于候选实现本身、且 env 与持久账本未受破坏时，将候选崩溃计为该版本的运行表现。在配置允许的本阶段恢复/重试耗尽后结束该阶段，丢弃未接收草稿，env 继续此前已接收的委托与撤换；下一预定阶段如仍有研究预算，使用同一封存候选和最后已提交的任务状态继续，不修补代码、不重新选择版本、不倒回市场补单。

若原定期间仍完整执行，且证据、信息边界、账本和成本均合格，则照常计算期末收益，并保留崩溃阶段、失败尝试和恢复记录；不因为表现差而剔除样本，也不额外增加临时收益罚分。阶段崩溃和整次 Episode 的可评分性分别记录，恢复失败不会清除原持仓或既有委托。

错误归因由 runtime 的退出、异常和宿主健康证据支持，evaluate.validity 按固定政策判断。模型服务不可用、平台进程故障、必要数据缺失、账本损坏、信息泄漏以及无法明确归因的异常不能直接算作候选自身缺陷；继续采用对应的受阻/失败与质量政策，不以模拟零收益替代不可评测状态。该候选崩溃政策已确认，尚未实现。

### 已确认：期末持仓与收益计分

主指标保持用户指定的收益率最大化，本次已确认采用任务期末账户净值收益率。无中途外部资金流时，收益率为 `期末净值 / 期初净值 - 1`；期初净值从配置和初始账户快照取得，本次为 200000，计算不写死该分母。env 提供包含实际交易费用及适用债务/融资成本的净值快照，evaluate 不重复扣费；研究成本继续由 budget 单独报告。

已确认终点为配置期间最后一个交易日的收盘估值，本次解析为 08-07：未卖出持仓按该时点的固定估值政策计入净值，不额外制造清仓成交、不延长到下一交易日，也不把盘后窗口的新消息当作收盘前已知信息。盘后复盘仍可完成，但不追改用于评分的收盘快照。

估值政策及其数据由 env 管理，evaluate 固定计分时点并引用同一估值政策；缺少可用价格、停牌、公司行为及特殊情况按定稿 D05 估值或阻断，不能临时挑选更有利的价格。收盘净值终点评分已确认；若以后允许中途外部资金流，需配置对应收益计量规则，不能直接套用上述简式。

## 资源与版本比较

用户已确认正式版本比较采用同等总成本，保留 token_cap=null。每任务成本额度按定稿 D08 的标定公式解析；真实标定尚未执行，本轮不启动付费试验。

按用户授权，采用定稿 D08 的基线标定与额度派生公式，正式比较前冻结每任务总成本预算。计量包含整个 Episode 中主 agent、subagent、重试、历史检验和相关计算；外层提出修改的成本另列并计入整项实验总成本。这样仍无直接 token 数量上限，但会受总成本约束。

记录收益随成本变化的轨迹。预算耗尽、主动结束、无改进停止、失败和取消分别记录；停止与有效性政策见定稿 D08～D09。

## experiment、runtime、budget 与 trace 的执行契约（草案）

### experiment：一次实验的唯一生命周期

experiment 拥有实验定义、候选版本和 Episode 的持久记录，复用已有任务执行所有权。其职责是解析配置、预检、排队、固定窗口推进及收集评测结果，不在 HTTP 或 CLI 进程中运行长时模型任务。

生命周期建议为“草案 → 预检 → 排队 → 运行 → 评测 → 完成”，并保留 blocked、failed 和 cancelled 等独立终态。名称为设计概念，不是当前新增的数据库状态。运行中再记录当前 Episode 和盘前、环境撮合、盘后等阶段；预算耗尽等原因单独记录，不能用一个 failed 混盖所有结果。

预检同时验证配置组合、历史交易日历和数据覆盖、分钟级成交能力、允许模型/数据访问、预算计量能力及产物存储。一次版本比较固定相同的任务清单、环境、资金制度、预算政策和指标；候选实现/允许配置是比较变量。数据或评分规则变更产生新实验定义，不能加入原实验排名。

### runtime：只执行被授予的工作

runtime 接收由平台绑定好的候选版本、Episode、决策窗口、证据视图和资源授权，不让模型自己选择或改写这些身份。它管理主/子 agent 进程、输入输出契约、取消、重试及崩溃回收；研究内容和如何委托仍由内层决定。

每个 Episode 只有一个主决策者。子任务的并发数、超时和重试参数可配置，实际启动统一检查窗口和预算；子任务不能直接挂单、改变资金制度或获得更宽的数据视图。当前 LAgent 委托实现为顺序执行，后续可配置并发属于新增能力，不假称已存在。

窗口关闭后禁止新模型调用，也禁止后台子任务或延迟回调继续产生研究决策。窗口固定模拟时间、现实耗时分列的政策见定稿 D03；runtime 必须执行这项政策，不能只在调用开始时检查一次。

### budget：计量、预留、结算和停止

budget 保存独立的研究成本账本，每项费用绑定实验、候选版本、Episode、窗口、agent、逻辑动作和实际调用尝试。模型输入/输出/缓存使用量、计算、检验和数据调用等按声明口径记录；重试和失败尝试的实际消耗不能遗漏，外层提出候选的费用另列并纳入整项实验总成本。

区分原始 usage、按固定价格表换算的费用和实际账单：采用统一价格表作为比较成本时必须明确标记，不能将其表述为已经支付的账单。计价单位、价格版本、计量范围及免费资源如何折算全部进入配置。

启动有成本的工作前先原子预留额度，结束后按实际计量结算并释放多余预留，多个 subagent 共享该 Episode 的同一额度。取消或失联后，未知消耗保留待核对状态，不能立即释放成可用预算；同一尝试重复收到回执也只能结算一次。

需要明确区分严格成本约束与调用边界上的停止：如果后端不能限制单次调用最大支出或及时提供 usage，仅在调用结束后统计不能保证不超限。不得通过偷偷添加 token 数量上限伪装成满足“不限 token、严格等成本”；应验证后端支持的资源约束方式，记录实际成本和任何超额，并按预定评测有效性规则处理。当前 executor 记录 usage 不等于已经具备严格成本执行能力。

### 断点恢复：保持同一份事实

恢复单位是已持久化的实验状态和动作记录，不是重新猜测一遍策略。配置、模型版本、历史时钟、证据视图、账户和已计费用保持原值；模型会话可以重建，但只注入该时点允许且已记录的公开任务状态，不承诺重新调用模型输出完全一致。

提交计划、委托接受与资金预留、成交与账本变更、窗口切换及费用结算都需要稳定的操作身份。模型结果已经持久化而动作尚未执行时，从该动作继续；委托或成交已经执行而调用者未收到回执时返回已记录结果，不再次挂单或落账。现有 LAgent 的模型动作留存和重放可复用，但尚无 Episode 账户/成交断点，不能直接视为交易回放恢复已经完成。

技术中断从最后一个可核验状态继续；主动取消终止工作并保留账本及费用，不自动恢复。显式重跑产生新运行及独立初始账户，前次尝试的消费、失败和结果仍保留；不能挑选重跑中最高分的一次假装只有一次评测。

### trace：可查询的执行事实

trace 至少关联实验、候选版本、Episode、决策窗口、主/子任务、逻辑动作、实际尝试、证据、委托和账本事件；同时记录模拟时刻与现实执行时刻。操作者能看到当前阶段、尚未完成的动作、费用预留/已结算/未知余额以及最后进展，恢复后不会丢失关联。

查询视图按调用者区分：操作者可以审计隐藏评测，当前内层只能读取其窗口允许的证据和任务状态，optimizer 只能读取实验允许的选择反馈。审计存储不得成为隐藏行情、其他候选表现或未来复盘结果进入当前模型的旁路；不采集或展示模型私有推理。

### 已确认：研究预算耗尽后的执行

已确认研究额度不可再授权新调用时，停止主 agent、subagent 和模型复盘，放弃未提交的草案；已被 env 接受的当日限价单、撤单及受限撤换流程继续按原规则执行，其中预定替换单只能在依赖确认并校验通过后提交，不能加入新决策或跨日续单。env 继续推进到配置的测试终点，对剩余持仓按已确定政策计价，evaluate 给出完整期间的收益及 budget_exhausted 原因。

为使这个结束流程仍遵守每任务总成本约束，应在总额度内预留必要的环境推进、结算和评测资源，agent 不能占用这部分预留；预留数值及校验可配置，实际尾段费用也计入同一任务成本。不能声称预算已经全部花完后免费执行剩余计算。

只有时间范围已完成、账户/证据质量合格且成本满足该实验规则时，才可将上述结果纳入正式比较。若剩余执行所需证据或资源不足，应标记不完整/受阻，不制造一个提前终止但貌似完整的收益率；手动取消或基础设施故障也不自动套用正常预算耗尽政策。

这是当前实验已确认的预算耗尽处理行为；停止政策仍属于实验配置，但不能在看到收益后临时改选或缩短测试期间。

## optimizer 的候选版本契约（草案）与已确认首版范围

optimizer 是实验平台的调用者，核心动作是提出一个新的 LAgent 版本并根据正式比较结果决定下一步。它不维护独立账本或评分器，也不能修改正在运行的 Episode；自动提案循环已确定放在下一阶段。

### 一轮候选版本的生命周期

1. 读取当前基线版本、实验规格、允许修改的字段/实现范围，以及该实验允许暴露的历史比较反馈。
2. 生成候选补丁及简短的改进假设，明确父版本和预期改善的行为；修改只作用于隔离的候选产物。
3. 平台验证修改范围、配置和执行契约，封存候选实现、配置、依赖与内容哈希。越界修改直接拒绝并留痕，不让候选自行声明已通过验证。
4. 通过同一 experiment/evaluate 入口，在固定任务、环境、资金制度、总成本及反馈规则下评测候选。所有失败、取消、超额和重跑都保留；不只存成功结果。
5. evaluate.comparison 根据预先固定的规则给出可比性、指标差异和是否满足晋级条件。optimizer 只能在合格候选中选择下一基线，不得自行修改分数或跳过门槛。
6. 记录保留/淘汰、比较证据及决策摘要，按配置的迭代或停止规则继续。被选为实验基线不等于覆盖当前业务 LAgent 配置或部署候选代码。

最小候选记录包含稳定身份、父版本、实现与配置引用、内容哈希、公开改进说明和对应实验/评测引用；最小比较记录包含基线与候选身份、实验规格哈希、任务覆盖、有效性、指标差异、成本及选择结果。详细记录契约和拟交付 CLI 操作见定稿 D09～D12，不作为当前可调用能力。

optimizer 提出候选的模型、资源和停止参数可配置，与被测 LAgent 的研究成本分项记录。其上下文只包含允许的选择反馈；最终留出任务的结果不能回流形成下一候选，持续消耗的验证集须明确标为调优集。

### 提交方式与自动化范围

手工提交和自动提交应复用同一候选注册、评测及比较契约，注册记录分别标明来源。这样未来接入 optimizer 时只新增提案和选择循环，不重新实现实验、账本、预算或评分。

首版范围已确认先完成内层运行和实验平台：可配置创建实验、提交一版 LAgent、完整执行盘前/盘后 Episode、查看证据和成本、比较基线与候选，并用进化树呈现版本分叉及测试证据。修改 LAgent 先由操作者或编码任务完成并显式提交候选，自动外层提案循环随后接入。

首版树中必须标明手工或编码任务提交来源，不能把这些分支写成已经发生的 optimizer 自动进化。范围已确认，但具体执行/评分 Interface 仍在设计中，本轮不开始实现。

## 已要求：LAgent 进化树（交互与记录草案）

进化树回答“为什么在这里分叉、分别测试什么、依据什么选择下一步”。它展示外层候选版本的演进，不把主/子 agent 的任务树或每次模型调用混成版本节点；节点详情可继续钻取这些执行记录。

### 节点、分支与测试

- 根节点是实验采用的初始基线，版本节点是一个有稳定身份和候选产物引用的 LAgent 方案。父子关系表示从哪个版本修改而来；相同版本的多个任务、重复运行和重试挂在节点详情下，不伪装成新版本。
- 分叉边记录父版本、候选来源、改动说明、测试前提出的假设和对应差异引用。若关键节点提出多个备选方案，可显式记录分叉批次，把同一研究问题的并列候选放在一起；不能仅因创建时间接近而事后认定它们是一组分叉实验。
- 分叉不意味着同时执行。候选由 experiment 按配置和已有队列规则安排，树如实显示排队、运行、待比较等状态，首版不额外承诺并发 Episode。
- 版本状态、评测有效性和选择结果分别展示：未测试/运行/完成是执行状态，数据受阻或失败是有效性事实，保留/淘汰/尚未决定是选择结果；失败节点没有虚构的零收益。
- 当前基线路径高亮，保留被淘汰、失败、取消及未选中的分支。基线晋级产生新的选择事件，不改写版本父子关系和旧的选择历史。

关键分叉必须记录当时已知的动机，例如“检验精简上下文是否在相同预算下提高收益”或“比较不同研究委托方式”。这些是可公开的假设与决策摘要，不是模型私有推理；后续解释追加为新记录，不能覆盖测试前的假设来配合结果。

节点摘要建议展示版本、改动标题、来源、评测覆盖、主指标、研究成本和选择状态。相对父版本/当时基线的指标差异只有在同条件比较成立时显示；环境、日期、任务集或预算不同则标注不可直接比较，不绘制误导性的提升箭头。

同一版本在不同实验中的分数保留为独立评测引用，树按当前实验规格展示相应结果；不维护一个跨任务、跨预算的“版本唯一收益率”。当前基线也属于指定实验的选择状态，不是所有实验共享的永久最好版本。

### 模块归属

| 模块 | 与进化树的关系 |
| --- | --- |
| `experiment` | 拥有候选身份、父版本、来源、分叉批次和评测关联；保存不可变产物及选择记录的引用 |
| `optimizer` | 后续生成分叉假设和候选提案，按正式比较结果产生选择；首版人工提交采用同一契约 |

### 首版交互建议

默认在实验详情显示整棵树及当前基线路径。支持缩放/平移、折叠展开分支、定位当前基线，以及按来源、状态和改动类型筛选；折叠和筛选不删除历史，界面明确显示隐藏的节点数量。

点击节点打开详情：改动假设、代码/配置差异、父版本、分叉批次、所有评测与失败、成本明细，以及选择证据。选中同一分叉的多个候选后，可对照相同任务上的收益、有效性和成本；关键节点可跳转到分叉前后的一组事件，复核当时为何保留或淘汰。

查询采用服务端分页和按需加载子树，分页尺寸/渲染数量等运行参数可配置，不设置不可调整的树深或节点数截断；候选 ID、父关系及事件序号保证断点刷新后仍能定位。历史回放视图按事件时刻展示当时已完成的结果，不把后来的成绩冒充当时选择的依据。

操作者可以在树中审计隐藏评测，但 optimizer 和内层的查询仍执行各自反馈边界。需要对外分享或导出时，沿用同一可见性投影，不能通过树的下载内容向当前优化任务泄漏最终留出答案。

### 已确认：允许从历史及淘汰版本重新分叉

已确认允许从任意保留了候选产物的历史版本发起新分支，包括曾被淘汰的版本，以检验此前未尝试的修改方向。新分支必须记录选择该父版本的假设，并重新完成同条件评测；从淘汰节点派生不意味着原节点恢复为基线，也不继承其他分支的测试成绩。

首版按单一父版本表达树关系；若一个候选借鉴其他分支，记录参考来源但不冒充多父合并。是否未来引入真正多父版本合并需要单独定义 lineage 语义，不能悄悄改变树的含义。允许从淘汰版本重新分叉已确认，其他字段和交互仍属于本节设计建议。

### 分支比较与已确认晋级主指标

父版本和晋级对手是两个角色。父版本解释候选如何产生，晋级对手是当前实验的基线；从旧淘汰版本改进的新候选，不能仅凭超过旧父版本就替代当前基线。比较记录固定当时基线身份及指标，树可以展示“相对父版本变化”和“相对当前基线变化”，但两者都必须有相同实验条件下的有效评测依据。

如果评测期间基线发生变化，原比较仍引用原对手；需要按当前基线重新比较后才能做新的晋级决定。只有候选版本、完整实验规格、任务及预定重复运行均一致的已完成评测才能按声明的复用政策引用，不把其他条件下的旧分数直接搬过来。

#### 已确认：复用同条件已有测试

比较新分支时允许直接引用当前基线已有的完整、合格测试，复用单位是确定的原始测试记录及预定样本集合，不是复制一个收益数字。相同候选版本、完整生效实验配置、任务与角色、研究预算及价格表、模型配置、环境/评分版本、声明的数据快照和搜索政策均须匹配；发生实质变化则重新评测可比基线。

复用不会形成一次新的 Episode，也不能将同一记录复制成多个重复样本。要求新增独立重复运行时必须实际启动新测试并生成新记录，旧结果不能充当新样本；用于正式均值的样本集合预先固定，不能从同版本的多次结果中挑最高一次。缺少预定样本或存在无效样本时，不能靠复用其他成功记录掩盖覆盖问题。

experiment 查找和关联原测试记录，evaluate 检查复用资格及完整样本后比较，trace 显示本次比较引用了哪些历史记录及原执行时间。budget 保留原测试实际成本，实验累计成本按执行身份去重；本次仅做比较的新增成本另计，不能把复用说成原测试没有成本。

复用不宣称重新验证了当前模型服务或搜索结果，也不保证今后重跑会得到同一轨迹。服务变化、数据更新或希望重新测量随机波动时可显式发起新运行；新运行保留独立身份，是否进入正式比较按预定样本政策决定，不能看完分数再替换旧样本。此项比较政策已确认，尚未实现。

已确认主指标采用固定任务集的平均期末净收益率：每个任务先平均预定重复运行的收益，再在各任务间按预先指定权重汇总；默认等权。任务数、日期、持续长度、重复次数、权重、最小改善幅度和稳定性门槛均是配置项，具体数值不在本轮选定。

候选须先通过完整性、质量和成本可比性检查，再比较主指标。重复运行用于展示波动，不能只取其中最高收益；数据受阻或失败结果保留且不能静默从均值分母去掉。回撤、换手、研究成本和单任务差异作为诊断展示，不临时混进另一个优化目标。

任务集可配置为单一期间以完成首个案例，也可配置多个行情区间；单一案例的提升只说明该任务的表现，不作为跨行情泛化结论。公开开发、用于选择的隐藏验证与最终留出任务仍分别管理，最终留出任务不进入晋级分数。

“默认以固定任务集的平均期末净收益率作为晋级主指标”已确认。不同任务时长的可比性、稳定性门槛、同分处理及晋级的完整判定方法仍需在该基础上细化并在实验前固定。

### 已确认：满足预设条件后自动更新实验基线

首版允许自动晋级实验基线：候选完成全部预定评测，evaluate 确认数据、账户、成本与样本完整性合格，并满足预先配置的收益改善及适用稳定性规则后，experiment 自动将其记为当前实验的新基线，不必为每次选择另行人工点击。选择政策在实验创建时固定；具体数值阈值及完整判定方法仍须配置，不以“自动”代替缺失的晋级规则。

晋级提交时再次核对当前基线身份与比较记录一致，避免多个已完成候选依据同一个旧基线互相覆盖；若基线已变化，先对新的当前基线重新比较，必要评测不齐时保留待比较状态。原比较结果、旧基线历史及新选择事件全部保留，进化树能显示谁在何时因哪些测试结果成为基线。

自动晋级只更新实验内的基线引用，不改写已经封存的候选，不替换运行中的 Episode 版本，不发布到业务 LAgent 配置。首版候选仍由手工或编码任务提交，按预设规则选择已有候选不等于已经实现下一阶段的自动提案 optimizer。此项自动选择政策已确认，尚未实现。

## 已确认：每个版本的全部测试记录保留

每次针对已注册版本的测试在预检/执行前就建立 Test Record。记录覆盖未开始即受阻、排队、运行中、通过、预算耗尽后完成、失败和取消等实际生命周期，不要求产生收益报告才出现在版本历史中。

一版 LAgent 可以关联多个实验、行情区间和重复测试，所有记录分别保留；同一次测试中的模型重试作为尝试记录挂在该测试下。技术恢复仍属于原测试的追加历史，显式重跑产生新测试身份并指向原记录，不把两者混为一次最优结果。

### 每次测试保留的内容

| 内容 | 保留要求 |
| --- | --- |
| 版本与实验身份 | 候选、父版本、提交来源、实验规格、任务、重复编号、重跑关联及实际内容版本 |
| 配置与输入来源 | 原始/生效配置、模型和数据/规则版本、历史信息截点、证据引用及哈希 |
| 生命周期与原因 | 预检、阶段、开始/结束时刻、停止原因、失败/受阻原因、取消及恢复事件 |
| 研究与执行 | 已记录的公开研究动作、主/子任务及调用尝试、盘前计划、委托、成交/拒绝/到期与账户变化 |
| 计量与结果 | 预留/已结算/未知费用、实际 usage、净值轨迹、单次收益及有效性；无有效收益时明确缺失而非填零 |
| 比较与选择 | 哪次聚合或比较引用了该测试、当时对手、权重和评分政策、晋级或淘汰依据 |

experiment 拥有测试身份、配置与版本关联；trace 保存追加事件及其产物索引，budget/env/evaluate 提供各自拥有的事实。终态结果不能被重跑覆盖；如需更正或按新评分政策重算，新增有来源关联的更正/评分记录，保留原结果和当时晋级决定。

聚合分数保存所引用的具体 Test Record 集合、权重、预定重复计划与评分政策版本，能从平均值追溯到每一次结果。新增额外测试不自动改写既有聚合和晋级历史，必须生成明确的新比较记录；额外测试也不能偷偷替换预定计划中的失败运行。

### 进化树与查询

点击任意版本可看到全部测试，按实验、日期、任务、状态和重复运行筛选，并钻取每次测试的动作、成本、账户及证据。节点上显示成功/失败/受阻/取消等数量与所用聚合记录，不能只显示最高分或最后一次测试；详细状态名见定稿 D09。

树的淘汰、折叠、筛选和版本停用均不删除测试。记录采用持久存储和可恢复备份策略，不设置自动过期或仅保留最近若干次；显示分页或缓存清理不得删除源记录，永久留存也不是要求一次把全部日志加载到界面。

候选实现、配置快照、平台产生的测试结果和审计事实纳入被引用产物的保留范围。外部原始数据继续遵守各自的数据保留政策；若其内容已不可用，测试记录仍保留来源、哈希和明确的可重放性状态，不将“测试记录保留”误报为可以永远重新取得所有外部数据。

“保留”与“暴露给 agent”是不同规则：操作者可查全部测试，内层和 optimizer 仍只得到允许的反馈视图。保存或导出历史不会解除隐藏评测和未来信息隔离，也不包含模型私有推理。

## 配置与可观测性

### 已确认：数值全部配置化

影响实验业务或运行行为的数值由其拥有模块声明配置，包括默认值、单位、允许值、含义及校验，不散落为实现中的隐式常量。CLI 和未来 WebUI 通过同一配置契约读写并展示实际生效值；一次实验使用完整解析后的 Experiment Specification，不能依赖后来变化的默认配置。

| 数值类别 | 配置归属 | 当前案例或待设内容 |
| --- | --- | --- |
| 研究启动、首个交易日、末日或持续交易日数 | experiment 的任务期间；evaluate.suite 引用它 | 08-02 启动、08-03 至 08-07；不写死五日长度 |
| 窗口时刻、信息截点、窗口内时间推进 | env.clock | 当前盘前早于 09:30、盘后晚于 23:00；具体启动时刻待设 |
| 本金、初始持仓、信用额度、保证金和资金政策参数 | env.account | 当前本金 200000；资金制度及适用参数另选 |
| 费率、价格/数量单位、各类市场数值规则 | env.market_rules | 从明确配置或带生效时间的市场规则版本解析 |
| 行情粒度、流动性比例、成交价模型参数、滑点及证据阈值 | env.execution，数据能力由 env.data 提供 | 参数均待具体模型确定；须符合正式评测要求 |
| 数据窗口、查询行数/字节数、缓存时效、拉取批量和限流/重试 | env.data 或其复用的数据提供方 | 复用现有参数也须在实验中记录实际值及来源 |
| 每任务成本上限、价格表、成本预留和计算计量参数 | budget | 同成本比较；金额待基线标定 |
| 模型超时、重试、并发和取消等待参数 | runtime | 由明确配置及受支持能力决定 |
| 研究步数、子任务数、上下文长度和搜索参数 | 内层配置；runtime/budget 负责平台约束 | 当前不设 token 上限；其他值不得暗中增加固定限制 |
| 重复次数、任务权重、比较阈值和计分参数 | evaluate | 作为实验规则预先固定，不能看分数后调整 |
| 外层迭代数、停止阈值和候选生成参数 | optimizer | 可配置，自动外层在下一阶段接入 |

这些配置项描述应具备的设计能力，不是当前已经存在的完整 schema。字段不能因实现方便被设为不可调整的五天、固定股票数量或固定重试次数；真正不支持的值由拥有模块明确校验并说明，不静默截断或替换。

所有数值可配置不改变单主 agent 的模式语义，也不允许 optimizer 修改当次实验环境。数学公式常量、单位换算、模型名称和证券代码中的数字不作为数值调优参数。市场制度中的数值应由版本化规则或显式实验覆盖提供；采用非真实制度的覆盖时须标识为假设环境，不能混作真实市场规则评测。

### 测试期间的配置与解析

研究启动时间、交易期间和最终复盘窗口是不同概念，不能只用一个天数描述。建议交易期间支持两种输入方式：首个交易日与末交易日，或首个交易日与持续交易日数；采用显式模式选择，另一表示由平台派生，不能维护两份相互冲突的日期和天数。

持续长度按交易日计，不按自然日加数；使用 env 提供的版本化交易日历解析周末、节假日及实际交易时段。研究启动必须落在该任务允许的窗口并早于首次计划截止；非交易日起点、非法长度、缺失日历和区间矛盾在启动前报告，不擅自移动日期。平台保存实际交易日列表、全部窗口和派生末日，任何长度都不能绕过数据覆盖检查。

当前案例可表达为研究启动日期 2026-08-02、首个交易日 2026-08-03、持续交易日数 5；精确启动预设为 23:05:00+08:00，见定稿 D03，末日按已验证日历派生为 2026-08-07。以后改变日期或天数无需修改模块实现。

配置分为三种状态：用户填写的原始配置、合并预设及规则引用后的生效配置、运行中的账户与任务状态。experiment 保存前两者及来源/版本/哈希，env 维护最后一项；trace 允许查看某个值来自显式输入、预设默认还是市场规则，并比较两次实验的配置差异。

未限定的资源项应有明确的无限制表示，不能用零、缺省字段或一个很大的数字混代。本次 token 上限仍为空值；其他字段是否允许无限制及空值含义由其配置契约明确规定。本案例资金制度等已由定稿选择预设；需要真实数据或成本标定才能解析的必需值保持 unresolved，不为让实验看起来可运行而填入占位值。

每次实验固定一份可复核配置：任务和数据版本、决策窗口及模拟时间政策、信息边界、模拟委托契约、交易与成交规则、公开/隐藏划分、模型与推理档位、资源政策、停止条件、评分和版本晋级规则；同时声明允许调优的字段。改变平台条件产生新实验定义；在允许范围内改变研究搜索或委托实现/配置产生候选 LAgent 版本，分别固定，不在运行中悄悄改变。当前实验的禁止唤醒及盘前/盘后限制属于已指定平台条件，不能由 optimizer 调整。

外层候选只能修改被测 LAgent；评测器、隐藏数据权限、审计记录及评分规则属于实验环境。若需修复评测器，产生新评测版本并重跑可比基线，不将评测器变化计为 agent 改进。

观察路径：实验 → 候选 LAgent 版本 → Episode → 盘前/盘后窗口 → 研究计划和决策 → 主/子 agent 动作与模型尝试 → 数据证据 → 模拟委托与成交判定 → 得分与版本选择结果。可查代码差异、父版本、数据截点、耗时、usage、成本、错误和选择依据；盘中仅产生环境执行记录，不产生 agent 研究动作，不依赖模型私有推理。

操作者可检查隐藏评测证据，但这些观察数据不能通过日志读取、共享文件、缓存、报告或后续上下文泄漏给当前内层任务。相同候选和数据支持执行复核；模型随机性意味着不能承诺重新调用模型得到完全相同结果。

## 现状与接入缺口

已有基础：版本化 LAgent 配置、单主 agent 委托、数据产品、共享研究队列以及持久化动作/调用记录。

待建设：候选 LAgent 隔离执行、连续 Episode、历史时间控制、可核验的历史搜索、模拟账本与成交引擎、公开/隐藏评测隔离、总成本计量和跨版本比较。此前 2026-08-02 数据边界预检未通过，旧测试没有生成真实回测结果；本设计不将其视为可运行基线。

当前业务研究输出不具备模拟动作契约。实验内的模拟操作需建立专用边界，不能把既有 research finish 报告直接当作可执行操作。

## 决策确认历史（剩余设计已收敛）

已确认：正式版本对比采用相同的每任务总成本预算，同时保持不设 token 数量上限；额度按定稿 D08 公式经基线标定后解析并冻结。

已确认：外层优化器的可修改范围限定为内层 LAgent 实现与允许调优的配置，外层平台规则在同一实验中保持只读，已记录 ADR-0101。

已确认：固定一版 LAgent 在历史时钟下跨窗口保留研究和决策状态，隐藏评测的允许窗口中仍可调用模型与 subagent；不要求先封存独立策略程序。

已确认：禁止唤醒；只在当天 09:30 前盘前研究、计划并挂单，当天 23:00 后复盘；盘中仅 env 执行，见 ADR-0102。

已确认：首版盘前模拟挂单限定为当日有效普通限价单，未成交部分到期失效、次日重新决策；交易范围限定为沪深 A 股，排除北交所。

已确认：资金制度是可配置的实验条件。模块设计采用 env.account 拥有和执行规则、experiment 固定快照、budget 只管研究成本；不再将“采用纯现金制度”作为全模块的待确认前提。具体制度及其参数在创建实验时配置，当前案例预设为 cash_equity_v1，其他制度按实现能力显式校验。

已确认：普通限价单正式评测以历史分钟行情为最低数据要求，特殊情形仍按成交模型要求更细证据，见 ADR-0103；具体成交模型见定稿 D06。

已确认：测试结束时按最后一个交易日收盘的账户净值计算收益，未卖出持仓计入估值，不强制清仓；估值政策版本化并由 env 提供净值快照。

已确认：持续日期、交易日数及所有业务/运行数值均可配置，当前数字只属于案例预设；实验启动后生效配置固定，见 ADR-0104。不再逐项询问某个数字是否需要配置化。

已确认：研究预算耗尽后停止 agent 研究，由 env 将已接受委托和持仓推进到原定测试终点；在总成本额度内预留必要环境和评测资源，不自动续单、清仓或提前截断期间，见 ADR-0105。

已确认：首版交付完整内层测试平台及候选版本对比，自动外层 optimizer 放到下一阶段；进化树属于首版交付，标明手工/编码任务来源，未来复用同一契约呈现 optimizer 自动分叉。

已确认：允许从任意有候选产物的历史版本重新分叉测试，包括曾被淘汰的版本；新分支重新评测，原版本的淘汰记录保持不变。

已确认：默认晋级主指标为预先固定任务集的平均期末净收益率，任务内先平均预定重复运行，任务间默认等权；任务、权重、重复数及改善/稳定性门槛均可配置。晋级对比当前基线，父版本仅表达来源。

已确认：每个版本的所有测试记录永久保留，成功、失败、受阻、取消、重复运行及尝试历史都可查询；重跑不覆盖旧记录，树中的淘汰不删除历史，见 ADR-0106。

已确认：盘前包含 09:25 结束时的最终开盘竞价结果，在其实际公开后冻结快照、09:30 前提交计划；现实研究耗时不推进模拟时间，所有主/子任务共享同一窗口信息边界，见 ADR-0107。

已确认：盘前计划整份校验、整份接收；任一委托非法或整批资源不足时整份退回，在同一盘前窗口与预算内修正重提，后续各笔委托仍分别判定执行结果。

已确认：不预支回款；允许在开盘竞价卖出成交后，用按账户政策已可用的净回款在竞价后重新挂单。盘前细分为两个预定阶段，各阶段独立快照和整份计划校验，竞价后不回滚竞价前成交，09:30 起仍禁止 agent 决策。

已确认：竞价前阶段同时允许买入和卖出，使用该阶段已有可用资金、信用额度及可卖持仓，并独立校验成交证据。

已确认：允许竞价后、09:30 前对竞价遗留委托预提交撤单，由 env 在市场规则允许时执行；确认前不释放旧单资源，旧单先发生的成交保持有效。

已确认：首版纳入盘前写定参数、撤单确认后由 env 自动重挂同证券同方向 DAY 限价单的受限撤换流程；扣除旧单累计成交量，重新校验资源，不调用盘中模型。

已确认：成交模拟采用固定历史行情路径，不考虑模拟订单对后续走势的反向影响，保留申报时序、流动性限制、排队、滑点和费用校验。

已确认：只有发布日期的材料在该日期结束后才可见；web 搜索通过服务支持的历史截止条件筛选，并信任该结果，不做逐页历史版本验证。自有数据已有时间字段，但字段语义和历史可用时间需在 env.data 明确映射，不能把采集时间当作首次发布时间。

配置及模块接口已由定稿 D01～D12 收敛；搜索选择和历史可用时间映射已确定，真实数据覆盖与连接验收由 LE-003/004/015 交付，不视为已有运行能力。

已确认：原定 2026-08-03 至 08-07 作为首个开发/调优基准，可反复使用反馈改进候选；最终留出评测另选未参与调优的期间。

已确认：LAgent 普通计划错误被 env 正确拒绝后，即使该阶段未修正成功，仍继续原定测试；完整期间质量和成本合格时按实际期末收益纳入比较，错误次数单列诊断，不自动重跑或剔除差结果。

已确认：比较新分支时允许复用当前基线同条件下已有的完整合格测试，引用原始测试身份；独立重复运行仍实际执行，复用不增加样本数或重复计算成本。

已确认：候选满足预设有效性、收益改善及适用稳定性条件后自动成为实验的新基线，完整保留比较与选择历史，不改变运行中的候选或业务配置。

已确认：明确由候选自身造成的崩溃，在阶段内恢复耗尽后结束该阶段，下一预定阶段在预算允许时继续同版本；完整期间质量与成本合格时按实际收益计分，平台故障及无法归因的异常单独处理。

上述核心规则已整理为 [首版验收清单](lagent-experiment-acceptance.md)。剩余核心规则已形成[实施设计定稿](lagent-experiment-final-design.md)和 16 张开发 tickets；清单不是已通过的测试报告。本轮仅交付设计与任务，不恢复代码实施。

用户已授权设计者自行决定剩余核心规则；以上事项由实施设计定稿统一替代早期待确认列表。后续依赖是 tickets 中的开发与真实数据/模型验收，不继续逐项询问同一设计。

## CLI / skill 影响检查

本轮仅更新设计草案、领域术语及已接受的架构决策，不改变运行能力、API、命令、配置或操作流程，因此无需修改 CLI catalog 或 ahunter skill。实现阶段必须同步新增实验能力的 API、CLI、skill 与维护检查。
