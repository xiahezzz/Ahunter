状态：设计完成，开发 tickets 待实施。2026-09-09。用户授权由设计者决定剩余核心规则；本文不代表代码完成、数据预检通过或历史测试已经运行。

## D01 范围、模块和可变范围

第一阶段交付完整内层历史实验、手工或编码任务注册候选、版本比较、自动实验基线晋级和进化树。第二阶段才接入自动生成候选的 optimizer。业务研究 LAgent 继续只输出研究，实验模拟指令只进入独立 env，不连接券商、不写实际账本。

沿用 Weco 的内层完成任务、外层改进内层实现、相同成本约束及留出评测思路；这里评测的是跨日研究与模拟交易能力，不声称复现其代码优化基准或已证明递归自我改进。[Weco 原文](https://www.weco.ai/blog/first-evidence-of-recursive-self-improvement)

| Module | 拥有的复杂性 | 稳定 Interface |
| --- | --- | --- |
| ahunter CLI | 输入、分页、导出、异步状态呈现 | 调用本地 API；不另写调度、成交或评分逻辑 |
| experiment | 规格解析、候选封存、预检、任务与阶段编排、选择提交 | resolve / register_candidate / submit / cancel / read |
| env | 历史时钟、数据可见性、市场规则、账户和模拟执行 | create_episode / observe / query / submit_plan / advance |
| runtime | 候选隔离、单主研究、委托、模型调用和恢复 | run_phase / stop_phase |
| budget | 价格表、成本标定、原子预留和结算 | calibrate / reserve / settle / read |
| evaluate | 样本有效性、收益、预定样本聚合、晋级判定 | assess / compare |
| trace | 不可覆盖的事件、产物引用和查询投影 | append / read / export |
| optimizer | 分叉假设、允许范围内的候选修改与提案成本 | propose；随后调用相同 experiment Interface |

这是同一应用内的逻辑模块；experiment 通过现有 durable Research Request / Research Service 获得执行权，不创建竞争队列或独立后台调度器。env 内部规则不暴露成 agent 可以绕过的调用入口。

候选可修改研究实现、提示词、记忆组织、查询选择、委托策略及 allowlist 内的配置；不可修改 env、预算计量、评分、任务集、时间和权限限制。模型在本实验中固定 GPT-5.5 high，主/子 agent 均继承；其他实验可以显式改变模型。所有生效值在运行前解析并封存，运行中的修改产生新候选或新实验，不能覆盖旧身份。

## D02 配置原则与原案例预设

每个业务及运行数值必须声明单位、合法范围、默认来源、是否允许 null，并出现在可导出的 resolved specification。null 只在字段声明时表示无限制；缺失值是独立的 unresolved 状态。配置不能把证券数量改成负数、把时间顺序改成倒流或关闭必要审计；这些是合法性条件，不是隐藏的不可配置业务参数。

| 配置 | 本案例的决定 |
| --- | --- |
| task.start / trading_days | 2026-08-03 / 5；用版本化日历解析，预期结束 2026-08-07 |
| task.setup_at | 2026-08-02T23:05:00+08:00 |
| env.account | cash_equity_v1；初始现金 200000 CNY，初始持仓空，信用额度 0 |
| env.universe | 历史沪深 A 股，含主板、科创板、创业板及 ST；排除北交所、基金、债券、B 股 |
| account.entitlements | 模拟账户具备上述板块交易资格；与初始资金分开，不能用 20 万元推断真实开户资格 |
| model / reasoning | GPT-5.5 / high；必须由模型适配器确认实际可用，禁止静默替换 |
| budget.token_cap | null；没有另设累计 token 数量上限 |
| runtime.max_steps / total_subagents / total_queries | null；仍受阶段时长、成本额度和资源可用性约束 |
| runtime.child_concurrency | 4；主 agent 只有一个，子任务不再递归创建 agent，可由主 agent 继续委托任意研究 |
| runtime.call_timeout / phase_wall_timeout | 900 秒 / 3600 秒；计现实时间，不推进模拟时间 |
| runtime.transport_retries / candidate_recoveries | 每逻辑调用最多 1 次传输重试；每阶段最多 1 次候选恢复 |
| runtime.stop_grace / lease / heartbeat | 10 秒 / 60 秒 / 10 秒；到期 fence 旧 worker，回收进程 |
| env.execution | fixed_path_conservative_v1；连续竞价分钟模型与特殊场景逐笔模型，见 D06 |
| evaluate.repeats / task_weights | 每候选每任务 3 次；同角色任务默认等权 |
| evaluate.minimum_improvement | 净收益率绝对差 0.001，即 10 个基点 |
| evaluate.positive_repeat_fraction | 至少 2/3 的预定重复优于基线；见 D10 |
| evaluate.worst_repeat_regression | 最差配对重复收益率差不得低于 -0.01，即负 1 个百分点 |
| trace.retention | 测试记录永久；必要审计不可禁用；分页默认 50、上限 200，可配置 |

以上为实验预设，不把 5 天、20 万、时间、并发、阈值或重试次数散落到实现中。日期输入支持“起止日期”或“开始日＋正整数交易日数”；不能同时提供两种冲突定义。允许任意合法持续天数；缺少覆盖的日历或数据时保存草案并阻断运行，不缩短期间。

资金制度由 env.account 拥有。首版实现现金股票账户；注册式 policy 能接入其他制度，但未实现的融资、融券或外部现金流政策必须明确报 unsupported，不能把一个布尔开关伪装成完整支持。首例不追加/提取本金、不借款、不卖空；现金利息预设 0，可配置。

## D03 固定阶段与信息时钟

| 阶段 | 信息界限与快照 | 平台计划接收 / 执行 |
| --- | --- | --- |
| 初始研究 | 08-02 23:05 冻结；只使用届时合格信息 | 保存研究记忆，不发送次日订单 |
| 竞价成交前 | 交易日 09:24:00 冻结 | 09:24:30 接收整份计划；加申报延迟后进入尚未结束的开盘竞价 |
| 竞价后 | 事件截止 09:25:00；09:25:05 冻结已公开竞价结果与已可见自身回执 | 09:29:00 接收计划；市场重新接收申报后执行，不能回填竞价 |
| 盘后 | 交易日 23:05:00 冻结 | 只复盘和提交记忆；下一交易日必须重新确认计划 |

竞价后 5 秒是预设接收延迟，不能让 09:25 之后的新新闻进入研究；最终竞价结果必须满足事件时刻不晚于 09:25 且实际可用时刻不晚于快照。不能凭“应该已经公布”生成结果。必要结果/回执迟到导致数据质量受阻，不推迟或临时新增研究窗口。原始来源的事件时间、发布时间、采集时间均保留。

初始日与各交易日按上表调度；非交易日不另开阶段。末日盘后复盘仍执行并计研究成本，正式净值固定在末日收盘。阶段中主/子 agent 的现实调用、重试和计算不改变信息截点；现实耗时另列，不能据此宣称实盘可在几分钟内完成。

计划提交时刻与交易所接受时刻分开。申报与回执延迟分别预设 100 毫秒，可配置；交易所未开放接受时先排队，在下一允许时刻提交，再计延迟。开盘竞价、连续交易、收盘竞价及不可撤单时段按证券所在市场的历史规则，不以单一日程覆盖全部市场。[深交所交易规则](https://docs.static.szse.cn/www/lawrules/rule/trade/W020260424690713155663.pdf)、[上交所 2026 年修订规则](https://www.sse.com.cn/lawandrules/sselawsrules2025/stocks/exchange/c/c_20260424_10816482.shtml)

## D04 历史数据与搜索

选择独立实验数据适配器 local_historical_bundle_v1：从本机不可变、带 manifest 的历史数据包导入，提供历史股票池/日历、原始日线/分钟、开收盘竞价、逐笔/队列证据、停复牌、企业行动和规则。它不改变 Market Daily 的新浪唯一实时来源，也不在缺数时自动接入付费行情或备源。当前尚无满足此契约的真实数据包；接入与完整性报告是运行前置交付物。

| 数据类别 | available_at 决定规则 |
| --- | --- |
| MX 本地事件 | received_at；同时拒绝明显晚于界限的 source_created_at；不倒填本机未收到的消息 |
| 新闻/公告/财报 | 可信来源的首次公开时间及版本有效时间；只有日期则次日 00:00 可见；没有可信语义的旧记录按实际采集时刻可见 |
| 原始分钟/日线/竞价 | 经 manifest 证明其历史版本语义的事件结束/公布时间加声明延迟；无此证明则按实际观测时间，不单凭 trade_date 回填 |
| 衍生指标、复权序列 | 所有依赖 available_at 的最大值；只使用当时已知的企业行动，禁止使用未来复权因子 |
| 股票池、交易资格、规则 | 发布可用时间与业务生效区间同时成立；不能使用今天的幸存证券列表 |
| 回执、资金、持仓 | env 已提交事件加配置回执延迟；未确认预计回款不可见为可用资金 |

查询必须同时满足版本、事件界限和 available_at 规则。保留 fetched_at，不能将补采时间伪造为历史发布时间。现有新浪日线的 source_at=fetched_at、MX 的 received_at 和 Provider observed_at 不是可直接互换的字段。

搜索选择 Tavily 日期过滤适配器作为首个实现目标，配置服务引用，不在实验配置/trace 中保存密钥。它属于实验 env 的受控搜索接入，现有业务 Research Engine 的凭证与搜索策略不变；未有可用连接就报 search_provider_unavailable，不自动开户、购买或换成无过滤搜索。该服务提供日期字段及 publish/update 日期过滤，不能作为分钟级发布时间证明。[Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search)

适配器向调用者暴露 last_included_date，不暴露可自行放宽的原始日期参数。对任一当天快照默认只能搜索前一自然日及之前；初始 08-02 阶段因此搜索到 08-01 为止，当日精确时间材料只能来自合格自有产品。provider 的 end_date 包含性、时区和参数映射通过边界 fixture 固定；映射无法可靠覆盖目标日期时进一步收紧并记录，禁止放宽。关闭自动参数和生成式答案，预设 general/basic、最多 10 条结果、返回可用正文、30 秒请求超时、1 次重试，均可配置。

信任服务实施的历史日期筛选，不要求逐页历史存档验证；记录最终查询、日期条件、provider 版本、结果和明确时间元数据。发现明确未来元数据就拒绝该条。无日期结果可以在该信任政策下保留并标注 date_filter_trusted，不能改标为 timestamp_verified。直接 URL、重定向、内置模型搜索和 shell 联网均不得绕过 env；搜索结果内容只是证据，不能成为平台指令。

同条件缓存按 product/provider/版本、查询、截止、信任政策和语料世代命名；不把其他候选的查询历史返回给 agent。正式比较采用同一搜索采集世代及请求级不可变响应缓存，新查询可追加，已有查询不刷新；跨现实时间新增查询仍可能受索引变化影响，报告该限制。要求逐字重放时使用已保存响应；缺失响应或原文过期明确标为不能精确重放。

预检检查整个任务必需股票池与日历、数据时间语义和执行能力；无数据不能通过缩小股票池或让 agent 避开证券来伪造完整覆盖。可选研究产品调用缺失返回质量状态；成交、估值、账户与所声明必需产品缺失阻断正式计分。未来行情只供 env 推进，不能被内层目录、错误信息或 trace 泄露。

历史过滤只能约束工具和上下文，不能清除模型预训练中可能已有的历史行情知识；报告必须区分工具时间隔离与模型知识污染，不能声称绝对无前视。

## D05 市场规则、账户、费用与估值

市场规则包包含逐市场/板块/证券状态的生效区间、申报单位、价格档位、涨跌幅、无涨跌幅场景、价格笼子、停复牌与申报时段。价格上下限使用当日原始参考价和规则派生，不一律写成 10%，不使用后复权价格下单。规则包缺少目标区间即预检阻断；依法规修订更新版本，不让 optimizer 调整数值逃过限制。

账户分别记现金余额、可用/冻结现金、证券总量/可卖/冻结数量、应收应付和负债。现金账户买入证券的可卖时点、卖出回款可用/可取时点按规则包处理，不能把“可再次买入”和“可提现”混为一谈。买单冻结限价名义金额及最大适用费用；成交按实计费释放差额，卖单冻结可卖持仓。计划整批先验证再单事务冻结。

费用由版本化 fee_schedule 计算：券商佣金预设成交金额的 0.0003、每张产生实际成交的委托最低 5 元，最低费按整张单累计一次；预设佣金包含交易经手/监管费用，不能重复收费。印花税、过户费等法定费率按目标交易日从来源明确的规则包解析，不能缺失时取零；法定费率由数据/规则 ticket 核实并固化，本文不把尚未核实的费率写成当期事实。佣金是模拟假设，不表示用户实际券商费率。证券交易印花税存在明确的生效日变更，说明费用必须按历史区间绑定。[税务总局公告](https://fgk.chinatax.gov.cn/zcfgk/c102416/c5211343/content.html)

金额用 Decimal，费用到分采用 ROUND_HALF_UP；成交部分按订单累计应收费用差额入账。买单预留最小佣金，卖出第一次部分成交即预扣最小佣金，使竞价后可用净回款不高估；零成交委托不收费，撤换新单独立计佣金。费用包声明每项计费对象、税基、方向、最低费和取整，配置必须无重复费项。

期末 NAV = 现金＋证券市值＋合格应收－应付－负债；R = NAV_end / NAV_start - 1。本例没有外部现金流，初始 NAV 必须为正；研究成本不扣交易本金。每天按原始官方收盘价估值；整日停牌采用最近合格收盘价并执行期间企业行动，标记 stale_valuation，不因停牌本身作零估值或强平。

分红按权益登记确认应收、按到账日变为可用现金，税负按历史制度及持有期记应付/预留；尚未卖出的股息税使用截至估值时可适用的最高待扣税额预留，不能引用未来卖出日减少负债，规则确定后按实际调整；送转股份按登记和可交易时间分开处理，不能重复用复权价格补偿。配股等自愿认购默认不参与。退市/合并/特殊现金替代必须有可执行规则及可核验估值；缺失时 valuation_unsupported 阻断，不能沿用失效价格或任意归零。企业行动状态机与费用/估值数据齐备才可正式计分。

## D06 成交、排队与受限撤换

采用固定历史路径、不反馈市场冲击；以下是可审计模拟假设，不是历史上实际成交的断言。普通连续竞价默认 conservative_minute_v1，特殊情形用 queue_replay_v1；模型选择按预先固定场景路由，不能看到收益后换模型。

1. 普通模型只用委托在该分钟开始前已有效的完整连续竞价分钟；不使用申报所在分钟的高低点倒推申报之后机会，不把集合竞价计入普通分钟容量。
2. 买单仅当该分钟最高价＋1 个 tick 的不利滑点不高于限价时具备成交资格，模拟价为该值；卖单对称使用最低价－1 个 tick。触及限价或分钟跨越限价不保证成交，按保守模型记 model_no_fill；这是一项明确估计规则，不是数据缺失的替代值。模拟价必须满足限价及市场价格界限。
3. 每证券每分钟共享成交容量 = 历史成交股数 × 0.01，按规则包的成交数量精度向下取整；买卖两方向、所有本 Episode 委托共用，按有效接受时间和稳定序号分配。容量不足允许部分成交；相同分钟不在不同模型重复分配。不同 Episode 是独立反事实账户，各自使用相同外部行情。
4. 若行情涉及开/收盘竞价、封板买入/跌停卖出、停复牌集合竞价、同分钟撤单与成交竞争，必须使用能重建相关排队和事件顺序的证据。仅有一分钟 K 线、总成交量或五档快照不足以证明队列前方消耗量；缺失必要证据标 execution_evidence_missing，阻断受影响正式评分，不能一律算没买到。
5. queue_replay 在已固定的历史撮合价/逐笔事件上把模拟单按价优/时优插入虚拟队列，先消耗可证实的前方数量，再分配剩余可执行对手量，并受 1% 共享容量约束。撤单只能减少有证据的前方量，不把未知撤单全部当作排队改善；模拟单不改写后续真实盘口。竞价在同一历史成交价分配，使用截至匹配时刻的完整可重建委托和优先顺序；不能根据最终结果回溯提交。
6. 排队模型价格沿已证实历史匹配价，预设额外滑点 0 tick；分钟模型为上述 1 tick。各模型参数均封存。证据证明无可执行量时 no_fill 合法，证据不够时是质量失败，二者必须分别展示。

一份阶段计划为有序指令列表，最多一份成功接收计划；拒绝可修正重提。主 agent 接收成功后该阶段交易计划封闭，不能拆成多次计划绕过整批资源约束。通信重试用相同 plan_id，内容变化必须新身份；同身份不同内容报 conflict。

独立新买单只用提交时已可用资源，不能预支同计划卖单或预计撤单释放；按列表顺序只决定同时刻优先级，不能使前置卖单虚构现金。引用同一旧单的多个撤单/撤换，以及同一证券相互冲突的自成交计划，整份拒绝。前一阶段成交及有效订单不会被后一阶段拒绝回滚。

竞价遗留 DAY 单持续有效。竞价后预提交撤单/受限撤换在市场可接受时发送，确认前旧单继续成交。撤换固定证券、方向、新限价、旧新合计目标；目标不能低于接收时旧单已成交量。确认后数量 = max(0, 目标－旧单累计成交)，重新验证费用、资金、数量和市场规则。资源不足不缩量，不重新定价；目标已满足不挂新单；新单重置队列优先级。

撤换只使用确认后当前实际可用资源，多个已就绪流程按原计划序号处理；接收依赖流程不承诺未来资源、不提前冻结第二份旧资源。市场规则拒绝、撤单失败或到期分别记录，不无限重试；原单剩余部分按真实模拟状态继续。替换产生的新单不能被同一计划再次替换。DAY 单收盘后剩余失效，延迟撤换不得跨日自动重挂。

有交易所事件序号时按其排序；没有可比序号但时间精度不足以区分成交和撤单时，不凭排序默认值创造收益，转入证据不足。已有确切时序后的内部并列事件再以持久化序号排序，重复回放保持相同结果。

## D07 候选执行与内层 loop

候选封存源代码、提示词、依赖锁、允许配置、输入输出契约、产物哈希和父版本。候选内容可相同而有不同提案身份，标记重复内容；代码包与 lineage 提案分开，不把复用包当成独立测试。

每 Episode 一个逻辑主 agent，阶段间进程可以重建；记忆只从本 Episode 已提交产物载入。主 agent 通过 observe/query/delegate/submit_plan/finish_phase 工作；研究计算在隔离的 scratch 区，网络、生产数据库、宿主文件、其他 Episode 和隐藏评测不直接可达。子 agent 只能研究，继承同一截点、模型和预算，不能提交计划或扩大数据产品权限。

同一阶段可进行多轮研究、检查假设、委托和修正计划，但 env 不提供未来收益试算或重置当天行情。盘后以实际模拟回执和届时信息复盘；这就是交易任务的内层反馈。外层修改代码产生新版本，不能在 Episode 中自改封存实现。

max_steps 等 null 不代表可绕过成本、阶段期限和平台资源；所有模型调用与主/子计算都经过 budget。后台线程、子进程和迟到回调在阶段关闭时被 fence，只有仍持有有效阶段权限的结果可提交。生产 LAgent 当前顺序委托的实现不能据此标为已支持并发实验。

## D08 成本标定与停止

成本用版本化 USD 等价计价账本，模型 token/缓存/推理 usage、搜索服务用量、主/子计算、重试、env 与 evaluate 全部列账。实际供应商账单和估值成本分列；本地订阅不能直接当作模型调用免费。模型价格/usage 必须有适配器可核对的价格表与计量语义，未知费用保持 unsettled，不按零结算。

首版 budget 支持 explicit 金额和 calibrated 两种模式，原例选 calibrated。执行前使用封存初始基线，在调优任务上完整跑 3 次 calibration Episode，记录全部花费和错误但不参与晋级样本；没有完整、成本可核对的标定结果就阻断，不挑便宜或高收益运行。标定不设 token 上限，使用 D02 阶段超时；本轮只设计，不启动这些调用。

令 C 为三个标定运行研究部分成本的最大值，P 为该调优任务预定阶段数。每个正式任务的总额度 B = 向上取整到 1 USD 的 [1.25 × C × 该任务阶段数/P ＋ E]；E 是该任务完整 env/evaluate 的预留上界。1.25、3、取整单位和模型价格表均可配置并在首个正式比较前冻结。留出任务只按阶段数及预先测得执行资源尺度派生额度，不用其模型表现重新标定。改变额度产生新实验条件。

E 由已导入行情包大小、执行算法版本和在无模型回放上测得的资源包络解析：基准 CPU/内存时间包络乘 2 的安全系数，转换为统一计价单位。首次无模型预检必须证明包络可覆盖完整市场回放及计分；不能仅留一个任意比例后声称一定能完成。运行超过包络属于 platform_resource_failure，保留实际额外成本，结果无效，不通过提前停止行情来维持预算。

每次模型/搜索调用先原子预留可证明的最大费用，然后结算实际 usage；有限价格与供应商上下文/输出物理上界可用于费用上界证明，但不新增累计 token 配额。如果所选执行器无法提供计量及上界或可靠硬费用控制，正式等成本模式报 cost_capability_missing；不得用一个猜测平均单价和事后统计冒充硬预算。余款不足以预留即停止该调用，允许记录“仍有余额但不足以授权下一调用”。并发子任务共享一个原子预算，不各拿一份额度。

研究额度耗尽后停止所有模型，保留已接受计划和记忆，env 使用 E 推进到原始终点。候选正常 finish、阶段超时、研究预算耗尽、用户取消、故障分别记原因。外层生成候选成本单列，实验累计费用包含标定、所有真实重复、失败尝试和外层提案；基线记录复用只引用，不重复计算实际费用。

## D09 生命周期、幂等与恢复

实验草案和不可变实验定义分开；每次预检是独立记录。一个 Test Record 对应一个 candidate × task × repeat 的 Episode，Comparison Record 引用预定测试集合；补跑另建关联记录，不替换原样本身份。

Test 生命周期：created → preflight → queued → running → evaluating → completed；preflight 失败为 blocked，运行中的必要外部数据/能力缺失为 blocked，平台完整性或无法归因故障为 failed，用户停止为 cancelled。终态不反转；补齐依赖后创建 linked rerun。安全 worker 恢复属于原记录的追加 attempt，不是新样本。

阶段状态为 pending / active / closing / closed，结束原因独立记录。明确由候选引起的异常在阶段内最多恢复 D02 次，耗尽后结束该阶段；下一预定阶段仍以同版本和最后已提交记忆继续。普通计划拒绝及候选崩溃不自动剔除差收益；完整期间、数据与成本合格则正常计分。模型服务/宿主故障、泄漏或未知费用不得按“候选不交易、收益零”计分。

用户取消使 queued 立即终止；running 记录取消意图并在持久安全点停止主/子任务和回放，保留部分账户快照、原因与费用，不给正式收益分。预算耗尽不是用户取消，必须完成剩余回放。未知模型账单可后续追加核销记录，原终态与原比较不能被覆盖；重新评估建立新评估记录。

事件键包含 experiment/test/phase、动作或调用身份及 attempt；接受计划、账户冻结、模拟成交、费用结算、撤单释放和记忆提交各用唯一键保护。SQLite 事务保存状态、事件和 outbox；Artifact Store 先内容寻址原子落盘，后提交引用，失败孤儿可隔离，不删除已引用产物。

worker lease 有 fencing generation；旧 worker 在丢失 lease 后不能写入。模型外部调用无法证明 exactly-once 时保存 invocation request ID 与 unknown 状态，先核对供应商结果，不能盲目重发。确定可重试的传输错误追加 attempt，所有成本保留。阶段关闭后的模型输出记 late_result_discarded，不能提交订单或跨阶段注入记忆。

必要审计写失败立即停止新的副作用；恢复从持久事件重建，不能依据模型口述补账。同一执行日志重放必须产生相同账户与净值；模型本身不要求逐字确定性。

## D10 任务划分、评分、比较与自动晋级

原例调优期仍为 08-03～08-07，08-02 启动；新增预设选择验证期为 08-10～08-14、08-09 23:05 启动，最终留出期为 08-17～08-21、08-16 23:05 启动。均按 5 个真实交易日校验，不把日期字符串视为已验证日历。日期和持续天数全部可配置；这些是预留任务，尚未运行或确认未受历史反馈污染。

角色在首次运行前登记。调优反馈可完整用于分叉；选择验证的逐日行情/决策 trace 不提供给 optimizer，完成比较后只给汇总分、稳定性和晋级结论。其反复反馈是选择信号，不能再称最终未见数据。最终留出在候选选择冻结后，只对初始基线和最终选定版本运行一组预定测试，不反向用于本轮晋级。用户若查看并用于修改，记录 exposure，后续必须新建留出窗口，不能改名抹除。

默认每任务 3 次真实独立运行，预先产生 repeat IDs、任务顺序与随机种子计划。模型不支持 seed 时如实记录 unsupported；相同 repeat index 表示配对设计，不声称控制了模型随机性。基线与候选运行顺序按预先封存的交错次序执行，不能看到结果后加跑直至显著。

任务内平均 3 个期末净收益率，再按该角色预设权重平均。不同交易日长度默认分组报告，不能混入同一默认晋级平均；显式允许混合时必须冻结权重并标明是原始期间收益，不暗中年化。回撤、换手、未成交率、持仓集中度、研究成本、崩溃和拒单数是诊断；不暗中改写最大收益目标。

正式自动晋级使用选择验证任务集的平均净收益率；调优分帮助产生候选，不与验证或最终留出混成一个分。仅有原五日调优结果可展示分支优劣，但标记 tuning_only，不宣称完成正式泛化选择。

晋级要求：预定样本全部完成且有效；候选验证均值至少高于当前基线 0.001；对每个 repeat index 先跨验证任务加权，至少 2/3 的配对差为正，且最差配对差不少于 -0.01。等分、门槛未达或缺样本保持当前基线，分别记录 not_improved / unstable / inconclusive。这里是工程稳定性门槛，不是统计显著性声明；三次随机重复不能证明长期获利。

任何必要样本 blocked/failed/cancelled 均使原 Comparison inconclusive；不剔除后重算平均。数据/平台修复需要新比较样本计划并链接原失败记录；候选自身缺陷的合法低收益样本不得替换。完成、有效、同条件且属于预定样本计划的基线记录可复用；查询选择按身份和资格，不能按最高收益筛选。跨候选不复用模型输出或交易动作。

比较指纹包含实际候选包、任务日期/阶段、账户、数据语料世代、搜索政策、模型实际标识、执行器、费用、价格表、预算、评分版本与预定样本集。同实验当前基线变化时，以 compare-and-swap 提交选择；过期对比保留，重新与当前基线比较，不抢写指针。不同规格结果只能并列诊断，不能直接晋级。

## D11 永久记录、可观测性与进化树

候选节点保存 parent、hypothesis、diff/artifact、提交来源 manual/coding_task/optimizer、配置与包哈希。首版单父分叉形成树；允许从淘汰或失败历史节点分叉，只要父产物可读，旧状态保持。未来多亲本合并需要显式新模型，不能伪装成当前树的一条边。

每个节点展示所有测试状态数量、任务角色、每次重复收益/成本/有效性、引用的 Comparison 和晋级原因；测试记录单独下钻。实验基线是带历史的标记，不是覆盖节点属性；显示“父版本”和“比较对手”两条不同关联。关键分叉显示提出假设、修改范围、安排哪些实验、得到何种结果及何时淘汰/晋级。

运行视图显示当前阶段与模拟截点、现实耗时、主/子任务、工具查询、剩余预算/预留/待核销、计划接收/成交/撤单、数据质量和错误。可从任一成交反查计划、证据、模型及账户分录，从任一晋级反查确切样本。trace 不保存私有思维链，保存可观察消息、结构化理由及工具输入输出；凭证脱敏在持久化前完成。

原记录永久保留，重跑、修订、重新评分或树中隐藏节点都只追加关联记录；没有删失败或覆盖分数功能。外部原文按来源保留政策处理，原文过期仍保留合法元数据、哈希和 unavailable 状态；下载导出清楚区分可完全回放与仅可核对摘要/哈希。隐藏角色的隔离由宿主查询视图实施，不在前端靠折叠保护。owner 可以显式审计全部保留记录，读取隐藏明细会追加 exposure；平台不能判断用户是否在其他应用见过行情，所以未见声明还需记录其已知暴露情况。
