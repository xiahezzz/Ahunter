# LAgent 预定基线重复组复用

实现：`advisor/research/experiments/reuse.py`。复用原 typed Test、评估和费用身份，
不复制测试记录、交易动作、模型输出、账户投影或账单。属于 LE-011 内部接口，
不新增 API/CLI 或实际模型调用。

## 计划登记

`BaselineReuse.register` 接受当前 selection revision、原定义、完整拟议 TestPlan、
明确的 tuning/selection_validation purpose 和全部任务运行条件。calibration 与
final_holdout 不使用该入口。定义或当前基线已变、选择已冻结时拒绝新登记。

按 comparison plan 的永久登记序号寻找最早合格的完整基线重复组，绝不按 NAV
排序、挑单次最佳、拼接不同计划中的重复或优先选较新的高收益组。原组必须属于
当前基线 proposal/包，具有同一规格、任务、角色、seed 支持、repeat index/ID/
seed，以及相同的运行条件（语料/世代、模型、搜索、执行器、费用、价格、预算及
评分版本）。每个原 Test 必须完成，首个评估必须正式有效且绑定实际条件。缺失、
非正式或首评无效的组不能被后续补评冒名替换。候选一旦晋级，其原合格候选组可以
作为下一轮基线组；引用仍直接指向原始 Test，不建立复用链。

调用输入中基线槽位的 test_id 只是计划占位，返回的封存计划才是实际样本身份。
登记将基线槽位替换为原完整组的 Test IDs；任务、proposal、重复设计和交错顺序
保持原要求，候选槽位使用调用者预先给定的新 IDs。新计划保留原请求及解析结果，
并保存源计划/比较/Test/首评的 IDs 和哈希。不能用占位 ID 指定收益更好的来源。

复用计划与新候选 Tests 在一个写事务中提交；原基线 Tests 不新建、不改 plan_id、
状态、费用、账户或阶段。返回 tests 按新计划顺序排列，但其中原 Test 仍保留原
登记内容；new_test_ids/reused_test_ids 明确区分需要执行的测试和只引用的测试。
只应执行 new_test_ids。全局测试次数和费用按原 Test 身份计数，不因被两个比较
引用而翻倍。

同输入重试返回已封存的来源，即使之后较早的原组才变得合格，或当前基线已晋级。
修改请求需新身份，原计划不能重新解析。找不到合格完整组则不登记新计划或候选
样本，不把来源缺失当作空仓/零收益。原失败比较和原资格事实继续永久保留。

## 比较与晋级

ComparisonAssessments 冻结及重算时再次验证固定来源、当前比较的预期 selection
和确切运行条件。复用的基线允许来自源 plan_id 且已完成；其余候选 Tests 仍须
尚未开始。未经声明的普通计划不能引用旧 Test 来绕过登记检查。

比较继续覆盖全部预定样本，保留原首评哈希，并通过原晋级 CAS；复用不跳过阈值、
过期比较或留出隔离规则。整体比较的候选对/新样本集合自然不同；复用资格比较的是
原基线的完整运行条件与重复设计，新比较指纹同时包含实际新计划和源记录关联。
不同候选不能通过此接口取得原模型输出或交易动作。

## 验证和边界

新增 16 项测试，与原登记/评估/晋级/留出合计 121 项通过：只新增三个候选 Test、
原账单不复制、最早组优先于较高收益组、缺组不拼接、来源解析后不重选、种子/重复/
角色/定义/运行条件不符拒绝、提交前后中断、两连接同请求竞争，以及晋级候选组
转作下一轮基线。新候选初始账户、阶段、费用和调用投影仍为空。

正向样本使用合成已验收宿主评估契约，测试复用消费边界；真实 EpisodeAssessments
仍不能为 fixture 生成正式资格。实际数据、模型、计费资格采集与服务完整编排仍待
接通，本增量不产生真实历史收益或开放正式实验运行。
