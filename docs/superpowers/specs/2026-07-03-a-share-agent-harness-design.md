# A 股实时事件分析 Agent Harness 设计规格

- 状态：已确认设计，待用户审阅书面规格
- 日期：2026-07-03
- 时区：Asia/Shanghai
- 项目根目录：`a_hunter/`

## 1. 目标

构建一个运行在用户 Mac 上的模块化事件驱动 Harness。系统被动监听用户已登录且有权访问的 MX 网页 WebSocket 消息，只持久化指定 `rid` 的内容；使用 Tushare MCP 补充 A 股行情、指数、财报、公告、行业和资金数据；将经过脱敏、压缩和结构化的数据证据包交给当前 Codex 模型，生成 A 股 1–10 个交易日视角的盘前计划、收盘报告、模拟组合和每日复盘。

系统建立独立、确定性的评价与自测机制。AI 可以在严格门禁内调整提示参数、因子权重和候选策略，但不能自动修改或部署源代码，也不能绕过最大回撤限制。

## 3. 非目标与安全边界

- 不连接券商，不下达或转发实盘订单。
- 不承诺收益率或胜率，只输出可验证、可追溯的研究结果。
- 不绕过登录、验证码、站点访问控制、反爬虫或其他风控机制。
- 不主动发送 Socket.IO 业务事件，只被动接收用户有权访问的消息。
- 不保存 Cookie、访问令牌、Socket.IO 会话 ID 或 Chrome 调试标识。
- 不把完整原始消息、原始图片或账户状态提交给模型。模型只接收完成最小化处理的证据包。用户选择使用当前 Codex 模型，因此证据包会进入当前模型上下文。
- 不允许 AI 覆盖风险限制、删除历史记录或改写既有评价结果。

## 4. 总体架构

```text
已登录 Chrome / MX WebSocket
          |
          v
监听健康检查与瞬时帧缓冲
          |
          v
解码 -> RID 白名单过滤 -> 去重 -> 允许事件账本
          |
          +----> 本地图片下载、哈希、文字/图表提取
          |
          v
实体识别与事件标准化
          |
          +----> Tushare MCP 数据补全与历史回填
          |
          v
量化特征与带时点的证据包
          |
          v
当前 Codex：分析、预测、模拟组合、报告
          |
          v
独立模拟交易账本与评价脚本
          |
          v
每日复盘 -> Challenger -> 回测 -> 影子测试 -> 配置晋级
```

系统采用本地 SQLite WAL 作为事件、任务、预测、模拟交易和评价的权威状态库。批量特征和回测快照可使用 Parquet。所有模块通过带 `schema_version` 的数据对象或文件通信，支持独立测试、幂等重跑和历史重放。

### 4.1 模块边界

1. **Chrome 监听适配器**：检查目标标签页、监听器和连接状态；恢复页面级监听；只接收入站帧。
2. **解码与过滤器**：在内存中解码 `room_msg`，提取 `rid`，执行白名单判断，拒绝非目标消息。
3. **事件存储**：只追加允许事件；保存独立 `rid` 字段、消息身份、时间和内容哈希。
4. **媒体处理器**：仅处理允许事件的图片；下载、哈希去重并提取文字或图表摘要。
5. **实体与事件解析器**：识别公司、股票代码、行业、事件类型、事实/观点/传闻属性。
6. **Tushare 补全器**：由 Codex 在 Harness 运行中调用现有 MCP；返回值先经本地校验器规范化，再进入数据快照。
7. **特征引擎**：确定性计算趋势、量价、波动、相对强弱、估值、财务变化和行业动量。
8. **证据包构建器**：按 `as_of` 时间聚合最小充分信息，生成只读输入。
9. **Codex 分析器**：依据证据生成结构化预测、模拟组合变更和 Markdown 报告。
10. **模拟交易引擎**：独立执行 A 股交易约束、费用、滑点和硬风险规则。
11. **评价器**：使用未来到期后的真实行情对预测、组合、信源和策略版本评分。
12. **复盘与晋级器**：生成配置级 Challenger，执行回测和影子测试；禁止修改代码。

## 5. RID 白名单与事件数据模型

### 5.1 配置行为

配置文件 `config/allowed-rids.yaml` 提供 `allowed_rids` 整数数组。首期由用户稍后填写，默认值为空数组。

系统采用 fail-closed 规则：

- `allowed_rids` 为空时不持久化任何 WebSocket 消息。
- RID 缺失、类型非法或不在白名单内时，立即丢弃正文、图片地址和原始帧。
- 允许记录不含内容的匿名运行计数，例如“拒绝 12 条非白名单消息”，用于健康检查。
- RID 配置变更只影响随后接收的消息，不追溯删除历史允许事件。

由于 `rid` 只能在解码后获得，原始帧只存在于受限内存缓冲。过滤通过后，才允许把该目标事件的原始加密载荷保存到本地，以便审计和重放；非目标载荷不得落盘。

### 5.2 允许事件字段

`events` 表至少包含：

- `event_id`：内部不可变标识。
- `schema_version`：数据结构版本。
- `rid`：独立整数列并建立索引。
- `source_message_id`、`oid`：源消息身份字段。
- `received_at`：浏览器实际接收时间。
- `source_created_at`：源消息创建时间。
- `raw_payload_hash`：载荷哈希。
- `raw_payload`：仅目标 RID 可选保存的加密载荷。
- `decoded_text`：标准化文本。
- `parsed_content_json`：结构化文本与媒体引用。
- `content_hash`：跨消息去重辅助键。
- `ingest_run_id`：采集运行标识。

去重优先使用源消息 ID；缺失时使用 `rid + oid`；仍缺失时使用 `rid + source_created_at + content_hash`。相同输入重复运行不得新增事件。

## 6. 数据流与知识材料

### 6.1 标准化流程

1. 对允许事件解析文本和图片。
2. 识别股票代码、公司、行业、事件类型和事件发生时间。
3. 将内容区分为已验证事实、来源观点、传闻、广告或免责声明。
4. 合并语义重复消息，但保留每条原始事件与聚合事件之间的关系。
5. 使用 Tushare 补充截至分析时点已公开的市场和公司数据。
6. 计算确定性量化特征。
7. 构造证据包并执行完整性、时效性和未来数据检查。

### 6.2 历史材料与本地知识库

用户当前没有历史交易记录或个人复盘笔记。系统以以下材料冷启动：

- Tushare 近 5 年 A 股个股、指数和必要的复权行情。
- 近 3 年财报、公告、业绩披露和可用的行业数据。
- 启用后持续积累的目标 RID WebSocket 事件与允许图片派生信息。
- 每次预测、模拟交易、评价和复盘形成的系统自身履历。
- 每个 RID、事件类型和主题的时间衰减可信度统计。

知识材料必须保留来源、发布时间、采集时间、适用实体和内容哈希。初期采用可检索的本地数据与 Markdown 经验条目，不对模型进行微调，也不声称模型权重发生学习。

### 6.3 证据包契约

证据包必须包含：

- `as_of` 和交易日。
- 数据覆盖率、最新时间和缺失项。
- 市场状态、指数表现、成交与风格概览。
- 目标事件列表及证据 ID、RID、可信度和实体映射。
- 候选股票的量价、估值、财务、行业和催化信息。
- 当前模拟持仓、现金、成本和风险状态。
- 已到期预测的评价摘要。
- 当前 Champion 版本和允许调整的参数边界。

Codex 输出中的每个核心判断都必须引用证据 ID，并明确区分事实、推断、冲突证据和数据缺口。

## 7. 定时 Harness 流程

### 7.1 常驻监听

Harness 定期检查 Chrome、MX 标签页、页面监听器和 WebSocket 活跃状态。页面刷新、导航、监听器消失或连接重建后，Harness 在不绕过登录验证的前提下重新注入被动监听器。需要用户重新登录时停止恢复并明确告警。

监听过程中按小批次导出瞬时帧，完成解码、RID 过滤和事务入库。导出成功且事务提交后才能释放对应内存帧。所有任务使用幂等键，进程退出后可以安全重跑。

### 7.2 09:00 盘前计划

1. 验证上一交易日数据、Chrome 状态、RID 配置和 Tushare 可用性。
2. 读取 09:00 前已经公开的信息和最新可用行情。
3. 构建盘前证据包。
4. Codex 生成市场情景、关注行业、候选标的、风险和模拟交易意图。
5. 模拟交易引擎验证可成交性和风险约束；无法验证时拒绝生成成交。
6. 写入 `reports/YYYY-MM-DD/premarket.md`，并在 Codex 对话展示摘要。

### 7.3 23:30 收盘报告与复盘

1. 确认当日收盘数据和公告覆盖情况。
2. 更新模拟成交、持仓、净值和已成熟预测。
3. 运行独立评价脚本。
4. 构建收盘证据包并生成完整投资分析报告。
5. 复盘当日有效与无效证据、错误归因和数据缺口。
6. 必要时产生 Challenger 配置并启动离线评测。
7. 写入 `reports/YYYY-MM-DD/close.md`、`review.md` 和机器可读 JSON；对话展示摘要。

## 8. 报告与结构化决策

报告至少包含：

- 执行摘要与数据质量状态。
- 大盘环境、风格和行业轮动。
- 关键实时事件与可信度。
- 财报、公告及产业催化。
- 候选标的：逻辑、证据、入场条件、失效条件、止损参考、持有期限和置信度。
- 当前模拟组合、拟调整仓位及原因。
- 三种市场情景和应对方案。
- 冲突证据、未知项和风险提示。
- 当日评价与策略版本变化。

报告属于研究和模拟用途，必须带有非投资建议声明。置信度不等同于收益概率保证。

## 9. 模拟组合与交易规则

- 初始现金 100,000 元。
- 支持 A 股 T+1、100 股整数手、停牌、涨跌停和可成交性约束。
- 佣金默认万分之三且单笔最低 5 元；卖出印花税、过户费和其他费率按带生效日期的配置管理。
- 滑点为可配置参数，默认以成交金额和流动性分档计算；报告必须显示使用的费率版本。
- 09:00 产生的意图只能使用生成后第一个真实可成交价格模拟成交。
- 23:30 产生的调仓建议最早在下一交易日可成交时执行。
- AI 动态决定持仓数量、个股和行业集中度，但模拟交易引擎拥有最终否决权。
- 净值相对历史峰值回撤达到 35% 时，禁止新增风险仓位并触发强制降仓计划；恢复条件由固定配置定义，AI 不得覆盖。

## 10. 独立评价脚本

评价脚本不调用 AI 进行打分。它读取不可变预测、模拟交易、策略版本、市场真值和基准数据，输出 JSON 与 Markdown。

### 10.1 预测指标

- 未来 1、3、5、10 个交易日方向胜率。
- 实际收益与预测区间误差。
- Brier score 或等价概率误差。
- 置信度分桶校准。
- 高置信预测的样本量和命中率。

每个预测只在对应交易日窗口完整结束后评分。停牌等情况按评价配置顺延或标记不可评估，不可提前使用未成熟标签。

### 10.2 组合指标

- 扣除费用和滑点后的绝对收益。
- 相对沪深300超额收益。
- 最大回撤、波动率、夏普、Calmar。
- 胜率、盈亏比、持有时间、换手率和成本占比。
- 行业、个股、RID 和事件类型的归因。

### 10.3 审计检查

- 预测或证据是否使用 `as_of` 之后的数据。
- 模拟成交价是否当时可获得且可成交。
- 数据缺失是否被当作零值。
- 同一事件、预测或交易是否重复计入。
- 策略和费用版本是否完整。

发现关键审计错误时，该运行标记为无效，不进入策略晋级比较。

## 11. 每日复盘与策略晋级

AI 可以产生以下配置级候选变更：

- 证据选择和摘要提示参数。
- 信源、事件、行业和量化因子的权重。
- 候选过滤条件、持有窗口和仓位目标。
- 不突破硬风控的止损与降仓参数。

AI 不得自动修改源代码、数据库迁移、评价公式或安全边界。代码建议只能形成补丁提案和测试报告，等待用户批准。

默认晋级门禁：

1. 使用带 `as_of` 的滚动回测；至少 4 个样本外窗口，每个窗口不少于 63 个交易日。
2. 所有关键数据泄漏和成交审计检查通过。
3. Challenger 的样本外净绝对收益和净超额收益均高于 Champion。
4. Challenger 的方向胜率不低于 Champion 超过 2 个百分点；若胜率下降，必须同时提高盈亏比并改善净超额收益。
5. 最大回撤低于 35%，且不得比 Champion 恶化超过 3 个百分点。
6. 影子运行至少 20 个交易日，并积累至少 30 个已成熟预测；期间没有风险门禁违规。

门槛存放于版本化配置，可由用户修改。自动晋级只更新“当前配置版本”指针，不覆盖旧版本；任一硬门禁失败即继续观察或淘汰。

## 12. 故障处理与降级

- **Chrome 或登录失效**：停止监听恢复，保留已提交数据，要求用户恢复登录。
- **WebSocket 断线**：记录无内容健康事件；页面自行重连后重新验证监听器。
- **解码失败**：隔离目标 RID 的失败载荷并记录错误，不混入正常消息；非目标载荷仍不得保存。
- **Tushare 不可用或限流**：指数退避重试；报告标记数据缺口，不使用陈旧数据冒充最新数据。
- **图片失败**：保留允许事件和图片 URL 哈希，标记媒体不可用；不得凭空描述图片。
- **数据库事务失败**：整批回滚并使用同一幂等键重跑。
- **关键数据质量失败**：禁止生成新的模拟决策，只输出故障报告。
- **报告生成失败**：保留证据包和运行清单，允许相同版本重跑。

## 13. 自测与发布门禁

提供统一 `scripts/self-test` 入口，生成机器可读 JSON 和 Markdown 自测报告；关键失败返回非零退出状态。

### 13.1 单元测试

- LZString、AES-CBC 和 JSON 解码链。
- 使用每条消息时间选择日期密钥，包括跨午夜场景。
- 空 RID 白名单、单 RID、多 RID、缺失 RID 和非法 RID。
- RID 独立字段、索引查询和去重身份。
- 嵌套文本、图片 URL、图片哈希和允许内容处理。
- 实体映射和特征公式。
- 收益、超额收益、费用、滑点和最大回撤公式。

### 13.2 集成测试

- 瞬时帧到允许事件的完整管线。
- 非白名单正文、图片和载荷零落盘。
- SQLite 事务、崩溃恢复、重放和幂等。
- Tushare MCP 返回值的契约校验使用脱敏模拟响应。
- 证据包 `as_of` 截断和未来数据泄漏拒绝。
- A 股 T+1、整数手、停牌、涨跌停和费用。
- 评价成熟窗口、Champion/Challenger 比较和晋级门禁。
- 报告结构与证据引用完整性。

### 13.3 运行冒烟测试

- Chrome DevTools 可连接。
- 目标标签页和监听器状态可识别。
- WebSocket 连接存在且能被动接收入站帧。
- Tushare MCP 能返回小规模合法响应。
- 数据库可写、报告目录可原子更新、定时任务可触发。

普通自测使用合成和脱敏夹具，不依赖目标网站在线。需要真实 Chrome、登录或 MCP 的测试单独标记，默认不会在离线测试中运行。

## 14. `agents.md` 补全范围

在实现阶段更新现有 `agents.md`，至少写明：

- 系统目标、非目标和禁止实盘边界。
- 模块职责、数据契约与不可越权项。
- Chrome DevTools 和现有 MX 解码脚本的使用方式。
- `allowed-rids.yaml` 的 fail-closed 规则。
- Tushare MCP 的查询、缓存、时点和数据质量规范。
- 09:00 与 23:30 标准运行清单。
- 自测、评价、重放、故障恢复和报告命令。
- Codex 报告必须引用证据、披露缺失并区分事实与推断。
- Champion/Challenger 的配置变更和代码审批规则。
- 不保存凭据、不绕过访问控制、只处理用户有权访问的数据。

## 16. 分阶段交付

### 阶段 1：事件底座

- RID 配置与过滤。
- 监听健康检查和恢复。
- SQLite 事件账本、媒体处理和幂等重放。
- 自测框架和首批单元/集成测试。

### 阶段 2：数据研究

- Tushare MCP 规范化导入。
- 5 年行情/指数与 3 年财报/公告回填。
- 实体映射、特征计算、知识材料和证据包。

### 阶段 3：决策与评价

- 09:00 和 23:30 报告流程。
- 10 万元模拟组合、真实交易约束和成本模型。
- 独立评价脚本与 Markdown/JSON 输出。

### 阶段 4：进化闭环

- 每日复盘。
- Champion/Challenger 配置仓库。
- 滚动回测、影子测试、自动配置晋级和回滚。

## 17. 验收标准

1. RID 白名单为空时，没有 WebSocket 内容落盘。
2. 配置指定 RID 后，只有对应消息及其媒体进入存储，且 `rid` 是可索引的独立字段。
3. 页面刷新或连接重建后，Harness 能检测监听器状态并在授权边界内恢复。
4. 同一批消息重放两次不会产生重复事件。
5. 09:00 与 23:30 能生成包含证据引用和数据质量声明的报告。
6. 模拟组合正确应用 A 股约束、费用、滑点和 35% 回撤门禁。
7. 评价脚本只对成熟标签评分，并能检测未来数据泄漏和无效成交。
8. 自测覆盖关键模块；关键失败会阻止新模拟决策。
9. 配置级 Challenger 只能在回测和影子门禁全部通过后晋级。
10. 源代码变更、风险边界变更和实盘能力均不能由 AI 自动启用。
