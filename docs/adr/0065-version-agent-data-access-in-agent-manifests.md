# Version Agent Data Access in Agent Manifests

The WebUI displays each Research Agent version's exact Data Products, read-only Provider provenance, and product-specific feed scopes, but any access change is published as the next immutable Agent Manifest version rather than written to a mutable permission table. The access editor copies instructions, output contracts, query budgets, and implementation settings unchanged and exposes them read-only, deliberately avoiding a general-purpose Agent editor. Any Agent may be explicitly granted any published Data Product without a role-based whitelist; product dependencies may be materialized to build the selected product but are not themselves queryable unless also explicitly granted. MX access pins explicit RID Feed identities and offers no wildcard for future authorized RIDs, so adding a RID cannot silently expand an existing Agent's inputs; removing a pinned RID blocks that Agent and only its dependent Teams instead of exposing retained history or silently narrowing the input. Existing Research Teams continue to pin their prior Agent versions until the owner explicitly publishes a Team revision, preventing a configuration edit from silently changing the inputs or conclusions of an already defined Agent or Team.
